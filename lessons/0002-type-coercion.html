Bản chất Type Coercion: Thuật toán ToPrimitive, ToNumber, ToString

Giải mã toàn bộ ma trận ép kiểu ngầm (Implicit Coercion), cơ chế Autoboxing và làm chủ các câu hỏi phỏng vấn trắc nghiệm "quái đản" nhất.

⏱ ~15 phút · 🎯 Mục tiêu: Giải thích cặn kẽ từng bước chạy của ToPrimitive theo chuẩn ECMA-262, phân tích chính xác 100% các phép tính bẫy, và biết cách can thiệp bằng Symbol.toPrimitive.

🌉 Bắc cầu từ câu hỏi tư duy ở Bài 01

Ở Bài 01, chúng ta đã chứng minh Primitive types (string, number, boolean) là những giá trị thô lưu trực tiếp trên Call Stack, hoàn toàn không phải Object. Vậy tại sao ta lại có thể viết:

JavaScript 
const str = "hello";
console.log(str.toUpperCase()); // -> Gọi method như một Object!

console.log([] + {});           // -> Ra "[object Object]"?!
console.log([] - 1);            // -> Ra -1?!

Liệu JavaScript Engine có đang "đoán mò" (magic) ? Hoàn toàn không. Tất cả những hành vi trên đều được điều phối bởi 2 cơ chế nghiêm ngặt: Autoboxing (Wrapper Objects) và hệ thống thuật toán trừu tượng Abstract Operations (ECMA-262).

1. Autoboxing: Primitive gọi method như thế nào ?

Khi bạn truy cập một thuộc tính hoặc phương thức trên một giá trị Primitive (ví dụ: str.toUpperCase() hoặc (42).toFixed(2)), V8 Engine thực hiện cơ chế gọi là Autoboxing (Boxing):

  1. V8 tạm thời khởi tạo một đối tượng bọc (Wrapper Object) tương ứng trên Memory Heap thông qua constructor nội bộ: new String(str) hoặc new Number(num).
  2. Đối tượng wrapper này kế thừa các phương thức từ prototype tương ứng (ví dụ: String.prototype.toUpperCase) và thực thi hàm.
  3. Ngay sau khi phương thức trả về kết quả, đối tượng wrapper tạm thời này lập tức bị hủy và sẵn sàng để Garbage Collector thu hồi.
JavaScript — Minh chứng Autoboxing & Bẫy gán thuộc tính 
const greeting = "hello";

// 1. V8 tạo new String("hello") tạm thời -> gọi toUpperCase() -> huỷ wrapper
console.log(greeting.toUpperCase()); // "HELLO"

// 2. Thử gán thuộc tính mới vào primitive
greeting.myProp = 100;

// Trong Non-Strict mode: V8 tạo wrapper tạm, gán myProp = 100 vào wrapper đó,
// rồi huỷ wrapper ngay lập tức! Dòng dưới tạo wrapper mới hoàn toàn:
console.log(greeting.myProp); // -> undefined!

// Trong Strict Mode / ESM ("type": "module"):
// JS Engine lập tức ném lỗi: TypeError: Cannot create property 'myProp' on string 'hello'

2. Ba thuật toán cốt lõi trong ECMA-262: ToPrimitive, ToNumber, ToString

Khi JavaScript thực hiện các phép toán hoặc so sánh giữa các kiểu dữ liệu khác nhau, nó không ép kiểu tùy tiện mà tuân theo các Abstract Operations (Thao tác trừu tượng) được định nghĩa trong chuẩn ECMA-262 §7.1.

A. Thuật toán ToPrimitive(input, preferredType) (ECMA-262 §7.1.1)

Khi một đối tượng (Object/Array) cần chuyển đổi thành một giá trị nguyên thủy (Primitive), engine sẽ thực hiện theo thứ tự ưu tiên sau:

Quy trình thực thi của ToPrimitive 
1. Nếu đối tượng có phương thức [Symbol.toPrimitive](hint):
   -> Gọi phương thức này với hint ("number", "string", hoặc "default").
   -> Nếu trả về Primitive -> DỪNG và lấy giá trị đó.
   -> Nếu trả về Object -> Ném TypeError!

2. Nếu KHÔNG có Symbol.toPrimitive:
   -> Nếu hint là "string":
        Thử gọi .toString() -> nếu ra Primitive thì lấy.
        Nếu không, thử tiếp .valueOf() -> nếu ra Primitive thì lấy.
   -> Nếu hint là "number" hoặc "default":
        Thử gọi .valueOf() -> nếu ra Primitive thì lấy.
        Nếu không, thử tiếp .toString() -> nếu ra Primitive thì lấy.

3. Nếu cả 2 hàm đều không trả về giá trị Primitive:
   -> Ném TypeError: Cannot convert object to primitive value.
💡 Mặc định của Plain Object {} và Array [] trong JavaScript

Theo mặc định, phương thức valueOf() của Object và Array trả về chính nó (tức là Object), không phải Primitive!
Vì vậy, engine luôn phải chạy tiếp sang bước thứ 2 là gọi toString():

  • [].toString() → "" (chuỗi rỗng).
  • [1, 2, 3].toString() → "1,2,3".
  • {}.toString() → "[object Object]".

B. Thuật toán ToNumber(argument) (ECMA-262 §7.1.3)

Giá trị đầu vào Kết quả sau ToNumber Lý do & Ghi chú
undefined NaN Không thể biểu diễn thành giá trị số hợp lệ
null 0 Quy ước số học trong C (con trỏ rỗng = 0)
true / false 1 / 0 Boolean binary
"" (chuỗi rỗng / chỉ có space) 0 Bẫy phỏng vấn cực kỳ phổ biến!
"123" / "3.14" 123 / 3.14 Chuỗi số hợp lệ
"123abc" NaN Khác với parseInt("123abc") ra 123!
[] (mảng rỗng) 0 [] → "" → 0
[42] (mảng 1 phần tử số) 42 [42] → "42" → 42
{} (plain object) NaN {} → "[object Object]" → NaN

3. Giải mã ma trận toán tử: Phép cộng + vs Các phép toán -, *, /, %

⚡ Quy tắc vàng của Toán tử Cộng (+) (ECMA-262 §13.15.3)

Toán tử + làm cả 2 nhiệm vụ: Cộng số học HOẶC Nối chuỗi.
Quy tắc phân xử:

  1. Chuyển cả 2 toán hạng sang Primitive bằng ToPrimitive() (với hint là "default").
  2. Nếu ít nhất một trong hai giá trị sau khi chuyển là kiểu string → Ép toán hạng còn lại thành chuỗi (ToString) và nối chuỗi.
  3. Ngược lại → Ép cả hai sang số (ToNumber) và thực hiện phép cộng toán học.

Trái lại, các toán tử -, *, /, % không hỗ trợ kiểu chuỗi. Chúng luôn luôn ép cả hai vế sang số qua ToNumber():

JavaScript — Từng bước giải mã các biểu thức bẫy 
// Ví dụ 1: [] + {} -> "[object Object]"
// B1: ToPrimitive([]) -> [].toString() -> ""
// B2: ToPrimitive({}) -> {}.toString() -> "[object Object]"
// B3: Có chuỗi -> Nối: "" + "[object Object]" = "[object Object]"
console.log([] + {});

// Ví dụ 2: [] - 1 -> -1
// B1: Toán tử trừ -> Bắt buộc ép cả hai về Number
// B2: ToNumber([]) -> [].toString() -> "" -> ToNumber("") -> 0
// B3: 0 - 1 = -1
console.log([] - 1);

// Ví dụ 3: Thứ tự thực thi từ trái sang phải
console.log(1 + 2 + "3");  // (1 + 2) = 3 -> 3 + "3" = "33"
console.log("1" + 2 + 3);  // ("1" + 2) = "12" -> "12" + 3 = "123"

// Ví dụ 4: [1, 2] + [3, 4] -> "1,23,4"
// [1,2].toString() là "1,2", [3,4].toString() là "3,4" -> Nối: "1,2" + "3,4"
console.log([1, 2] + [3, 4]);

4. Kiểm soát toàn diện cơ chế ép kiểu với Symbol.toPrimitive

Từ ECMAScript 2015 (ES6), bạn có thể hoàn toàn kiểm soát cách một đối tượng bị ép kiểu bằng cách định nghĩa phương thức Symbol.toPrimitive. Phương thức này sẽ đè bẹp cả valueOf và toString:

JavaScript — Tùy biến hành vi ép kiểu 
const product = {
  name: "Bàn phím cơ",
  price: 1500000,

  [Symbol.toPrimitive](hint) {
    if (hint === "number") {
      // Gọi khi dùng trong ngữ cảnh toán học (+product, product - 500k)
      return this.price;
    }
    if (hint === "string") {
      // Gọi khi dùng String(product) hoặc template literal `${product}`
      return `${this.name} (${this.price} VNĐ)`;
    }
    // hint === "default": Gọi khi dùng toán tử + hoặc so sánh ==
    return this.price;
  }
};

console.log(+product);             // 1500000 (hint: "number")
console.log(product - 200000);     // 1300000 (hint: "number")
console.log(String(product));       // "Bàn phím cơ (1500000 VNĐ)" (hint: "string")
console.log(product + 50000);      // 1550000 (hint: "default")
🎙️ Góc phỏng vấn Senior: Cách trả lời chuẩn Top-Down

Câu hỏi 1: "Giải thích kết quả của hai biểu thức [] + {} và {} + [] trong JavaScript."

👉 Câu trả lời Senior (Top-Down):
"Biểu thức [] + {} luôn trả về chuỗi "[object Object]" theo đúng thuật toán ToPrimitive của toán tử cộng: mảng rỗng ép thành chuỗi rỗng "", còn object rỗng ép thành chuỗi "[object Object]", dẫn đến phép nối chuỗi.
Tuy nhiên, với {} + [], kết quả phụ thuộc vào ngữ cảnh thực thi:

  • Nếu viết trực tiếp ở đầu dòng trong Developer Tools Console, {} được trình phân tích cú pháp (Parser) xem là một khối lệnh rỗng (Empty Block Code), do đó chỉ còn lại biểu thức một ngôi +[], cho ra kết quả số 0.
  • Nếu bọc trong ngoặc đơn ({} + []) hoặc gán vào biến const res = {} + [], {} được coi là Object Literal và kết quả vẫn là chuỗi "[object Object]"."

Câu hỏi 2: "Cơ chế Autoboxing có gây rò rỉ bộ nhớ hoặc ảnh hưởng hiệu năng không ?"

👉 Câu trả lời Senior:
"Trong các JavaScript Engine hiện đại như V8, đối tượng wrapper tạm thời được cấp phát trên bộ nhớ Heap ngắn hạn (Young Generation / New Space) và bị Garbage Collector thu dọn cực kỳ nhanh chóng trong các chu kỳ Minor GC (Scavenger). Ngoài ra, V8 còn áp dụng kỹ thuật tối ưu hóa Escape Analysis để loại bỏ hoàn toàn việc cấp phát Heap nếu instance wrapper không bị rò rỉ ra phạm vi bên ngoài, do đó chi phí hiệu năng của Autoboxing là không đáng kể trong thực tế."

6. Câu hỏi tư duy (Bắc cầu sang Bài 03)

Quan sát 3 biểu thức so sánh kinh điển dưới đây và thử đoán kết quả:

JavaScript 
console.log(null > 0);   // -> false
console.log(null == 0);  // -> false
console.log(null >= 0);  // -> true (QUÁI LẠ?!)

👉 Nếu null > 0 là false và null == 0 cũng là false, tại sao null >= 0 (lớn hơn HOẶC bằng) lại trả về true ? Chuẩn ECMA-262 quy định thuật toán so sánh quan hệ (Relational Comparison) và so sánh bằng trừu tượng (Abstract Equality ==) khác nhau như thế nào ?
