1. Meta-programming là gì ? 13 Internal Traps của Proxy

Meta-programming (Siêu lập trình) là khả năng một chương trình có thể tự phân tích, sửa đổi hoặc tùy biến chính hành vi cốt lõi của ngôn ngữ runtime. Trong JavaScript, đối tượng Proxy bọc quanh một đối tượng đích (Target) và cho phép ta đánh chặn 13 thao tác nội bộ (Internal Methods) thông qua các hàm bẫy (Traps) :

Proxy Trap Thao tác JavaScript kích hoạt Hành vi mặc định tương ứng
get(target, prop, receiver) Đọc thuộc tính (proxy.foo, proxy[bar]) [[Get]]
set(target, prop, value, receiver) Gán giá trị (proxy.foo = 10) [[Set]]
has(target, prop) Toán tử kiểm tra tồn tại ("foo" in proxy) [[HasProperty]]
deleteProperty(target, prop) Toán tử xóa thuộc tính (delete proxy.foo) [[Delete]]
apply(target, thisArg, argList) Gọi hàm (proxy(...args), proxy.call()) [[Call]]
construct(target, argList, newTarget) Khởi tạo với new (new proxy(...args)) [[Construct]]
ownKeys(target) Lấy danh sách key (Object.keys(), for...in) [[OwnPropertyKeys]]

2. Tại sao LUÔN LUÔN phải dùng Reflect bên trong Proxy Traps ?

Một thói quen rất nguy hiểm của nhiều lập trình viên là viết trực tiếp target[prop] bên trong Proxy Trap. Điều này phá vỡ tính đúng đắn của JavaScript và là nguồn gốc của các bug mất reactivity cực kỳ khó debug !

⚠ Bí mật của tham số receiver trong Reflect.get

Hãy xem xét một đối tượng có thuộc tính getter kế thừa :

JavaScript — Bug mất Reactivity khi thiếu receiver 
const parent = {
  _value: 10,
  get value() {
    return this._value; // 'this' ở đây là ai ?
  }
};

const proxy = new Proxy(parent, {
  get(target, prop, receiver) {
    // SAI LẦM: return target[prop]; → 'this' trong getter sẽ trỏ vào 'parent' (Target gốc)
    // ĐÚNG ĐẮN: return Reflect.get(target, prop, receiver);
    return Reflect.get(target, prop, receiver); // 'this' luôn trỏ vào 'receiver' (Proxy instance) !
  }
});

Nếu bạn không truyền receiver vào Reflect.get, từ khóa this bên trong các hàm getter/setter sẽ trỏ thẳng vào đối tượng gốc (Target) thay vì đối tượng Proxy. Hậu quả là mọi thao tác đọc biến kế thừa sẽ bỏ qua Proxy hoàn toàn, khiến hệ thống reactivity không thể theo dõi (track) được dependency !

3. So sánh toàn diện: Proxy (Vue 3) vs Object.defineProperty (Vue 2)

Tiêu chí kỹ thuật Object.defineProperty (Vue 2) Proxy (Vue 3)
Cơ chế can thiệp Can thiệp ở mức từng thuộc tính cụ thể (Property level) Can thiệp ở mức toàn bộ đối tượng (Object level)
Hiệu năng khởi tạo ban đầu Rất chậm khi data lớn (phải duyệt đệ quy qua toàn bộ cây object ngay từ đầu) Cực nhanh (Lazy: chỉ bọc Proxy lớp ngoài cùng, khi nào truy cập object con mới bọc tiếp)
Thêm thuộc tính mới (Add property) KHÔNG PHÁT HIỆN ĐƯỢC (phải dùng hack Vue.set()) Tự động nhận diện 100% qua set trap
Xóa thuộc tính (Delete property) KHÔNG PHÁT HIỆN ĐƯỢC (phải dùng Vue.delete()) Tự động nhận diện 100% qua deleteProperty trap
Hỗ trợ Mảng (Array Mutation) Phải monkey-patch 7 phương thức mảng (push, pop, splice...) Hỗ trợ tự nhiên mọi chỉ mục (Index) và thao tác thay đổi mảng
Hỗ trợ Map, Set, WeakMap Không thể hỗ trợ Hỗ trợ trọn vẹn

4. Live-coding: Dựng Reactivity Engine tối giản (Trái tim Vue 3)

Chỉ với chưa đầy 40 dòng code, chúng ta có thể dựng lại hoàn chỉnh mô hình Reactive State Engine tương tự Vue 3 :

JavaScript — Vue 3 Minimal Reactivity 
let activeEffect = null;
const targetMap = new WeakMap(); // target → Map(key → Set(effects))

// 1. TRACK: Ghi nhận effect đang chạy vào danh sách phụ thuộc
function track(target, key) {
  if (!activeEffect) return;
  let depsMap = targetMap.get(target);
  if (!depsMap) targetMap.set(target, (depsMap = new Map()));
  let dep = depsMap.get(key);
  if (!dep) depsMap.set(key, (dep = new Set()));
  dep.add(activeEffect);
}

// 2. TRIGGER: Kích hoạt lại toàn bộ effects phụ thuộc khi dữ liệu đổi
function trigger(target, key) {
  const depsMap = targetMap.get(target);
  if (!depsMap) return;
  const dep = depsMap.get(key);
  if (dep) dep.forEach((effect) => effect());
}

// 3. REACTIVE: Bọc đối tượng bằng Proxy
function reactive(target) {
  return new Proxy(target, {
    get(obj, key, receiver) {
      track(obj, key);
      return Reflect.get(obj, key, receiver);
    },
    set(obj, key, value, receiver) {
      const oldValue = obj[key];
      const result = Reflect.set(obj, key, value, receiver);
      if (oldValue !== value) trigger(obj, key);
      return result;
    }
  });
}

// 4. EFFECT: Hàm tự động chạy lại khi phụ thuộc thay đổi
function effect(fn) {
  const effectFn = () => { activeEffect = effectFn; fn(); activeEffect = null; };
  effectFn();
}

5. Góc phỏng vấn Senior Frontend

🎓 Q1: Tại sao Vue 3 chuyển từ Object.defineProperty sang Proxy ? Nêu 3 điểm yếu lớn nhất của Vue 2 ?

Trả lời Top-Down chuẩn Senior :

"Vue 3 chuyển sang `Proxy` để khắc phục 3 nhược điểm cấu trúc của `Object.defineProperty`: (1) Vue 2 phải duyệt đệ quy mọi key khi khởi tạo gây nghẽn hiệu năng trên object lớn, trong khi Proxy có tính chất Lazy; (2) Vue 2 không thể phát hiện khi thêm mới hoặc xóa thuộc tính (`Vue.set/delete` bắt buộc); (3) Vue 2 không hỗ trợ mảng tự nhiên mà phải monkey-patch các phương thức mảng, trong khi Proxy theo dõi index mảng và thuộc tính `length` tự động."

🎓 Q2: Proxy.revocable() là gì và khi nào bạn sử dụng nó trong ứng dụng thực tế ?

Trả lời Top-Down chuẩn Senior :

"`Proxy.revocable(target, handler)` trả về một object gồm `{ proxy, revoke }`. Khi gọi hàm `revoke()`, đối tượng proxy bị cắt đứt hoàn toàn liên kết với target, mọi thao tác truy cập sau đó đều ném `TypeError`. Chúng ta sử dụng nó khi cung cấp dữ liệu nhạy cảm cho các plugin/script bên thứ ba không đáng tin cậy: sau khi plugin hoàn thành tác vụ, ta gọi `revoke()` để đảm bảo plugin không thể tiếp tục đọc hay ghi lén dữ liệu nữa."
