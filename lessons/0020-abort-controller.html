Bài 20 · AbortController & AbortSignal: Hủy request, Race Conditions & Stale Responses

Làm chủ vòng đời của async operations trong thực tế: hủy fetch khi người dùng điều hướng đi, xử lý hiện tượng race condition khi người dùng gõ nhanh (typeahead search) và tránh bẫy stale closure trong data fetching.

⏳ ~20 phút · 🎯 Mục tiêu: Triển khai đúng cách pattern cancel-on-supersede với AbortController trong mọi async UI, sử dụng AbortSignal.timeout và AbortSignal.any để xây dựng hệ thống timeout mạnh mẽ.

Người dùng gõ "j" → request 1 bay đi. Gõ tiếp "ja" → request 2 bay đi. Nếu request 1 chậm hơn request 2, kết quả của request 1 sẽ về SAU và ghi đè lên UI, mặc dù đó là dữ liệu cũ ! Đây là hiện tượng Race Condition / Stale Response — lỗi UI cổ điển nhất trong async data fetching.

1. AbortController API: Kiến trúc và Vòng đời

Chuẩn Web Platform giới thiệu 2 class phối hợp với nhau :

Class / API Vai trò Thuộc tính / Phương thức chính
AbortController Bộ điều khiển (Controller) — giữ quyền phát lệnh hủy .signal (thuộc tính trả về AbortSignal)
.abort(reason?) (phát lệnh hủy)
AbortSignal Tín hiệu (Signal) — truyền thông tin hủy tới các tác vụ .aborted (boolean)
.reason (lý do hủy)
.addEventListener('abort', cb)
AbortSignal.timeout(ms) Static factory tạo signal tự hủy sau N ms Thay thế pattern setTimeout + abort thủ công
AbortSignal.any([s1, s2]) Kết hợp nhiều signals, abort khi bất kỳ signal nào kích hoạt Hữu ích khi muốn kết hợp timeout + manual cancel

2. Pattern Cancel-on-Supersede: Giải pháp dứt điểm Race Condition

Đây là pattern thiết yếu trong mọi typeahead search, autocomplete hay infinite scroll :

JavaScript — Pattern Cancel-on-Supersede (React / Vanilla JS) 
let activeController = null;

async function search(query) {
  // Bước 1: Hủy bỏ request đang chạy trước khi tạo request mới
  if (activeController) {
    activeController.abort('Superseded by newer request');
  }

  // Bước 2: Tạo controller mới cho request này
  activeController = new AbortController();

  try {
    const response = await fetch(`/api/search?q=${query}`, {
      signal: activeController.signal  // Truyền signal vào fetch
    });
    const data = await response.json();
    // Chỉ cập nhật UI khi đây là request chưa bị hủy
    renderResults(data);
  } catch (err) {
    if (err.name === 'AbortError') {
      console.log('Request bị hủy, bỏ qua kết quả này');
      return; // Không cập nhật UI
    }
    throw err; // Các lỗi thực sự vẫn được ném ra
  }
}

3. Tích hợp AbortSignal với Timeout: Cách chuẩn của ES2022+

JavaScript — Kết hợp AbortSignal.timeout + manual cancel 
async function fetchWithTimeout(url, timeoutMs) {
  // Cách cổ điển (trước ES2022): setTimeout thủ công
  // const controller = new AbortController();
  // const timer = setTimeout(() => controller.abort(), timeoutMs);
  // ... clearTimeout(timer) khi xong

  // Cách hiện đại ES2022+: static factory tự dọn dẹp
  const response = await fetch(url, {
    signal: AbortSignal.timeout(timeoutMs)
  });
  return response.json();
}

// ES2023+: Kết hợp nhiều nguyên nhân hủy
const userController = new AbortController();

const response = await fetch(url, {
  signal: AbortSignal.any([
    userController.signal,       // Người dùng bấm Cancel
    AbortSignal.timeout(5000)  // Hoặc timeout sau 5s
  ])
});
💡 Trong React useEffect: Pattern cleanup chuẩn

Khi dùng useEffect với fetch trong React, luôn trả về cleanup function để hủy request khi component unmount hoặc dependency thay đổi. Đây là một trong những câu hỏi phỏng vấn Senior React phổ biến nhất !

useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/user/${userId}`, { signal: controller.signal })
    .then(res => res.json())
    .then(setUser)
    .catch(err => { if (err.name !== 'AbortError') setError(err); });

  return () => controller.abort(); // ← Cleanup function
}, [userId]);
