1. Trục 1: Mô hình bộ nhớ & Quản lý kiểu (Bài 01)

Kiểu dữ liệu Vùng nhớ lưu trữ Cơ chế truyền tham số Đặc tính bất biến
7 Primitives: String, Number, Boolean, Null, Undefined, Symbol, BigInt Call Stack (Nằm trực tiếp trong Execution Context) Pass-by-value (Sao chép giá trị nguyên bản sang ngăn nhớ mới) Immutable (Bất biến, không thể thay đổi nội tại giá trị)
Reference Types: Object, Array, Function, Date, RegExp, Map, Set Memory Heap (Call Stack chỉ lưu con trỏ tham chiếu 32/64-bit) Pass-by-sharing (Sao chép bản sao con trỏ tham chiếu đến cùng ô nhớ Heap) Mutable (Đột biến thuộc tính bên trong đối tượng)
💡 Cơ chế Autoboxing & Escape Analysis

Khi gọi method trên Primitive (ví dụ "hello".toUpperCase()), V8 Engine tạm thời bọc nó trong Wrapper Object (new String()) trên Heap. Nhờ kỹ thuật Escape Analysis, V8 phát hiện đối tượng không rò rỉ ra ngoài và tối ưu hóa loại bỏ việc cấp phát Heap, tránh hoàn toàn chi phí hiệu năng và rò rỉ bộ nhớ.

2. Trục 2: Thuật toán Type Coercion (Bài 02)

Toàn bộ cơ chế ép kiểu trong JavaScript đều tuân theo 3 thuật toán trừu tượng trong đặc tả ECMA-262 :

ECMA-262 §7.1.1

ToPrimitive(input, preferredType)

Biến đổi Object thành Primitive theo thứ tự ưu tiên :

  1. Gọi [Symbol.toPrimitive](hint) nếu có.
  2. Nếu hint là "string": gọi toString() trước, nếu không ra primitive thì gọi valueOf().
  3. Nếu hint là "number" / default: gọi valueOf() trước, sau đó mới gọi toString().
ECMA-262 §7.1.3 & §7.1.17

ToNumber & ToString

  • ToNumber(null) → 0
  • ToNumber(undefined) → NaN
  • ToNumber("") → 0
  • ToNumber("123") → 123 | ToNumber("12a") → NaN
  • ToString([]) → "" | ToString([1,2]) → "1,2"
  • ToString({}) → "[object Object]"

3. Trục 3: Ma trận so sánh bằng (Bài 03)

Biểu thức == (IsLooselyEqual) === (IsStrictlyEqual) Object.is() (SameValue) Giải thích bản chất
NaN vs NaN false false true IEEE 754: NaN không bằng chính nó. Object.is phân biệt chính xác.
+0 vs -0 true true false Bit dấu khác nhau trong bộ nhớ 64-bit IEEE 754.
null vs undefined true false false Quy tắc đặc biệt ECMA-262: null chỉ loosely equal với chính nó và undefined.
null vs 0 false false false == không bao giờ ép kiểu null sang 0 (chỉ >= mới gọi ToNumber).
[ ] vs 0 true false false [].toString() → "" → ToNumber("") → 0 == 0 → true.
[ ] vs ![ ] true false false ![] → false, sau đó [] == false → 0 == 0 → true.

4. Trục 4: Định danh kiểu dữ liệu chuẩn Senior (Bài 04)

KIỂM TRA CƠ BẢN

typeof (Primitives)

Nhanh nhất, chạy mức register CPU. Trả về đúng tên 7 primitives + function.

Lỗi C 1995: typeof null === "object" (Tag bit 000 trùng NULL pointer 0x00).

MẢNG XUYÊN REALM

Array.isArray(val)

Đọc trực tiếp internal slot [[Class]]. An toàn tuyệt đối trước cross-realm iframe và Web Worker (nơi instanceof Array sụp đổ).

PROTOTYPE CHAIN

instanceof (Class Instance)

Duyệt ngược chuỗi prototype chain. Không hoạt động với primitive literals ("abc" instanceof String → false).

TIÊU CHUẨN VÀNG

Hàm phân loại kiểu vạn năng: toExactType

JavaScript Utility 
function toExactType(val) {
  if (val === null) return 'null';
  if (val === undefined) return 'undefined';
  return Object.prototype.toString.call(val).slice(8, -1).toLowerCase();
}

5. Top câu hỏi phỏng vấn Senior then chốt của Module 01

🎓 Q1: Tại sao null >= 0 là true nhưng null == 0 lại là false ?

Trả lời Top-Down: Do hai toán tử sử dụng hai thuật toán trừu tượng hoàn toàn khác nhau trong chuẩn ECMA-262. Toán tử so sánh quan hệ >= chạy thuật toán IsLessThan(null, 0), thực hiện ép kiểu số ToNumber(null) → 0, và !(0 < 0) cho kết quả true. Ngược lại, toán tử bằng lỏng lẻo == chạy thuật toán IsLooselyEqual, có quy tắc độc lập: null chỉ bằng chính nó hoặc undefined, tuyệt đối không bị ép sang số 0.

🎓 Q2: Khi nào toán tử instanceof cho kết quả sai lệch ?

Trả lời Top-Down: instanceof gặp 3 điểm mù lớn : (1) Môi trường Cross-Realm (Iframe/Worker), nơi mỗi Realm có một bộ nhớ Heap và Prototype riêng; (2) Primitive literals vì chuỗi thô không có prototype chain trực tiếp; (3) Prototype Mutation khi bị can thiệp bởi Object.setPrototypeOf hoặc ghi đè Symbol.hasInstance.

🎓 Q3: JavaScript truyền tham số theo cơ chế nào ?

Trả lời Top-Down: 100% là Pass-by-value (chính xác hơn là Pass-by-sharing đối với Object). Khi truyền đối tượng vào hàm, JavaScript sao chép con trỏ địa chỉ bộ nhớ Heap. Đột biến thuộc tính bên trong hàm sẽ ảnh hưởng bên ngoài vì chung ô nhớ, nhưng gán lại biến (re-assignment) thì không ảnh hưởng vì chỉ thay đổi con trỏ cục bộ.
