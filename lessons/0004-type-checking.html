Bài 04 · typeof, instanceof & Kiểm tra kiểu đáng tin cậy

Giải mã lỗi thiết kế C-level năm 1995, bản chất Prototype Chain lookup, sự sụp đổ của instanceof qua ranh giới Realm (iframe), và tiêu chuẩn vàng Object.prototype.toString.

⏳ ~15 phút · 🎯 Mục tiêu: Hiểu rõ cơ chế xác định kiểu của JavaScript Engine, phân tích vì sao instanceof thất bại cross-realm, và tự xây dựng hàm kiểm tra kiểu chuẩn Production.

🌉 Cầu nối từ Bài 03

Ở bài trước, chúng ta đã hiểu sâu về các phép so sánh ===, == và Object.is(). Tuy nhiên, trước khi so sánh hoặc xử lý dữ liệu, bước đầu tiên trong mọi hệ thống production là kiểm tra kiểu dữ liệu (Type Checking). Nếu dùng sai công cụ để kiểm tra kiểu, toàn bộ logic phòng thủ phía sau sẽ sụp đổ.

1. Toán tử typeof & Lỗi thiết kế máy ảo C năm 1995

Toán tử typeof là cách nhanh nhất để kiểm tra các kiểu dữ liệu nguyên bản (Primitive types). Theo chuẩn ECMAScript, typeof chỉ trả về chính xác 1 trong 8 chuỗi ký tự cố định sau đây :

Biểu thức Kết quả typeof Phân loại Ghi chú tầng sâu
typeof undefined "undefined" Primitive Bao gồm cả biến chưa từng được khai báo (undeclared).
typeof true / false "boolean" Primitive Boolean nguyên bản.
typeof 42 / NaN / Infinity "number" Primitive Kể cả số vô tỉ hoặc NaN (Not a Number).
typeof 42n "bigint" Primitive Số nguyên vô hạn chữ số (ES2020).
typeof "Antigravity" "string" Primitive Chuỗi ký tự bất biến (Immutable).
typeof Symbol("id") "symbol" Primitive Định danh độc nhất (ES6).
typeof function(){} "function" Object đặc biệt Là Object nhưng có internal method [[Call]].
typeof {} / [] / /abc/ / new Date() "object" Reference Mọi object, mảng, regex, collection.
typeof null "object" Primitive Bẫy lịch sử nghiêm trọng nhất JS !
⚠ Tại sao typeof null === "object" ? Bản chất kiến trúc C năm 1995

Trong phiên bản đầu tiên của JavaScript (Brendan Eich viết trong 10 ngày năm 1995), các giá trị được biểu diễn dưới tầng C bằng một từ máy 32-bit gồm 2 phần : Type Tag (1-3 bits đầu) và Payload (con trỏ bộ nhớ hoặc giá trị) :

  • 000 : Đối tượng (Object) — payload là địa chỉ bộ nhớ trỏ sang Heap.
  • 1 : Số nguyên (Integer 31-bit).
  • 010 : Số thực dấu phẩy động (Double).
  • 100 : Chuỗi ký tự (String).
  • 110 : Boolean.

Giá trị null được định nghĩa là con trỏ rỗng (NULL Pointer, giá trị địa chỉ 0x00). Khi máy ảo đọc các bit định danh (tag bits), nó thấy toàn số 0 → trùng khớp hoàn toàn với Type Tag 000 của Object ! Do đó, hàm trả về chuỗi "object".

💡 Tại sao hội đồng TC39 không sửa lỗi này ?

Vào năm 2008 (thời điểm chuẩn bị ECMAScript 4 / 5), đã có đề xuất sửa typeof null thành "null". Tuy nhiên, khi thử nghiệm trên các trình duyệt thực tế, hàng loạt website trên toàn thế giới bị sập. Rất nhiều thư viện và mã nguồn legacy sử dụng đoạn kiểm tra :

JavaScript Legacy Check 
if (typeof val === "object" && val !== null) { ... }

Nếu đổi kết quả typeof null sang "null", nguyên tắc "Don't break the Web" (Bảo đảm tính tương thích ngược) sẽ bị vi phạm. Do đó, TC39 quyết định giữ vĩnh viễn hành vi này như một đặc tả chính thức của ngôn ngữ.

2. Toán tử instanceof & Giải phẫu Prototype Chain

Để kiểm tra kiểu của các Reference Type (Mảng, Date, Error, hoặc Class tùy biến), lập trình viên thường dùng toán tử instanceof. Nhưng bản chất bên dưới của instanceof là gì ?

Thuật toán OrdinaryHasInstance (Tương đương) 
// Biểu thức: obj instanceof Constructor
function myInstanceOf(obj, Constructor) {
  // 1. Primitives luôn luôn trả về false
  if (obj === null || (typeof obj !== "object" && typeof obj !== "function")) {
    return false;
  }

  // 2. Lấy prototype của Constructor
  const targetPrototype = Constructor.prototype;
  let proto = Object.getPrototypeOf(obj);

  // 3. Duyệt ngược chuỗi Prototype Chain đến khi gặp null
  while (proto !== null) {
    if (proto === targetPrototype) {
      return true; // Tìm thấy khớp địa chỉ tham chiếu!
    }
    proto = Object.getPrototypeOf(proto);
  }

  return false;
}
⚠ Hai điểm mù nguy hiểm của instanceof
  1. Không nhận diện được Primitive Literals :
    "Antigravity" instanceof String === false (vì chuỗi nguyên bản không có prototype chain trỏ tới String.prototype trừ khi được bọc bằng new String("Antigravity")).
  2. Có thể bị giả mạo / thay đổi runtime :
    Prototype chain có thể bị can thiệp bằng Object.setPrototypeOf() hoặc qua cơ chế ES6 [Symbol.hasInstance].

3. Cạm bẫy Cross-Realm (Iframe / Web Worker) & Sự ra đời của Array.isArray()

Đây là câu hỏi phân loại ứng viên Senior kinh điển nhất khi phỏng vấn về JavaScript Core :

☢ Hiện tượng: Tại sao arr instanceof Array trả về false ?

Một Realm trong JavaScript bao gồm một môi trường thực thi hoàn chỉnh : Global Object riêng (window trong tab chính, iframeWindow trong thẻ iframe), Global Scope riêng, và tập hợp các built-in constructors riêng biệt nằm ở các địa chỉ ô nhớ hoàn toàn khác nhau trong Memory Heap !

Kịch bản Cross-Realm kinh điển (Iframe / Micro-frontend) 
// Trong cửa sổ trình duyệt chính (Main Realm)
const iframe = document.createElement('iframe');
document.body.appendChild(iframe);

// Mảng được tạo ra từ Realm của iframe
const subArray = iframe.contentWindow.Array(1, 2, 3);

// So sánh Prototype Chain giữa 2 Realms:
subArray instanceof Array; // → FALSE ! Tại sao ?

// Giải thích:
// subArray.__proto__ === iframe.contentWindow.Array.prototype
// Nhưng window.Array.prototype lại nằm ở một địa chỉ ô nhớ hoàn toàn khác!
// iframe.contentWindow.Array.prototype !== window.Array.prototype

// CỨU TINH: Array.isArray() hoạt động xuyên Realm!
Array.isArray(subArray); // → TRUE (Chuẩn xác 100%)
✅ Tại sao Array.isArray() giải quyết được ?

Theo chuẩn ECMA-262, Array.isArray(arg) không hề duyệt chuỗi Prototype Chain. Nó kiểm tra trực tiếp Internal Slot [[Class]] (hoặc internal tag định danh mảng của V8 Engine). Bất kể mảng đó được sinh ra từ Realm nào, tab nào, hay iframe nào, internal slot của nó luôn được cộp dấu nhận diện mảng.

4. "Tiêu chuẩn vàng": Object.prototype.toString.call()

Nếu typeof bị lỗi với null và không phân biệt được các loại object, còn instanceof bị đứt gãy qua Cross-Realm, thì đâu là giải pháp tối thượng để định danh kiểu dữ liệu trong JavaScript ?

Đó chính là Object.prototype.toString.call(value).

Sức mạnh của Object.prototype.toString.call 
const toTag = (val) => Object.prototype.toString.call(val);

toTag(null);        // → "[object Null]"        (Chính xác!)
toTag(undefined);   // → "[object Undefined]"   (Chính xác!)
toTag([1, 2, 3]);   // → "[object Array]"       (Hoạt động cross-realm)
toTag(/abc/);       // → "[object RegExp]"
toTag(new Date());   // → "[object Date]"
toTag(new Map());    // → "[object Map]"
toTag(new Set());    // → "[object Set]"
toTag(async () => {}); // → "[object AsyncFunction]"
⚙ Cơ chế tầng sâu (ECMA-262 Specification)

Khi gọi Object.prototype.toString.call(O), thuật toán thực hiện :

  1. Nếu O là undefined → trả về "[object Undefined]".
  2. Nếu O là null → trả về "[object Null]".
  3. Chuyển O thành Object thông qua ToObject(O).
  4. Kiểm tra thuộc tính đặc biệt Symbol.toStringTag trên đối tượng. Nếu có giá trị chuỗi, dùng chuỗi đó làm Tag.
  5. Nếu không có, ánh xạ theo bảng internal slots chuẩn (Arguments, Array, Function, Error, Date, RegExp...).
  6. Trả về định dạng "[object " + tag + "]".

5. Xây dựng hàm kiểm tra kiểu chuẩn Production & Decision Tree

Dựa trên toàn bộ bản chất ở trên, đây là hàm tiện ích chuẩn senior giúp bạn phân loại chính xác 100% mọi giá trị trong JavaScript :

practice/type-checking.test.js — toExactType 
/**
 * Trích xuất kiểu dữ liệu nguyên bản và đối tượng chuẩn xác 100%
 * @param {*} value - Giá trị cần kiểm tra
 * @returns {string} - Tên kiểu viết thường: 'null', 'undefined', 'array', 'object', v.v.
 */
function toExactType(value) {
  // 1. Xử lý trường hợp null và undefined nhanh gọn
  if (value === null) return 'null';
  if (value === undefined) return 'undefined';

  // 2. Dùng Object.prototype.toString và cắt chuỗi '[object Tag]'
  return Object.prototype.toString.call(value).slice(8, -1).toLowerCase();
}
👁 Cây quyết định khi kiểm tra kiểu (Type Checking Decision Tree)
  • Cần kiểm tra Primitive thông thường (number, string, boolean, symbol, bigint, undefined) ? → Dùng typeof (hiệu năng cao nhất, thực thi trực tiếp tại CPU/Register).
  • Cần kiểm tra null ? → Dùng phép so sánh nghiêm ngặt val === null.
  • Cần kiểm tra Mảng ? → Luôn luôn dùng Array.isArray(val) (bất bại trước cross-realm).
  • Cần kiểm tra một Class Instance cụ thể trong cùng ứng dụng ? → Dùng instanceof.
  • Cần phân biệt Plain Object {}, RegExp, Date, Map, Set, hoặc Deep Clone / Serializer ? → Bắt buộc dùng Object.prototype.toString.call(val).

6. Góc phỏng vấn Senior Frontend

🎓 Câu hỏi 1: Tại sao typeof null === 'object' và tại sao lỗi này không bao giờ được sửa ?

Cách trả lời Top-Down chuẩn Senior :

"Đây là lỗi thiết kế cấu trúc dữ liệu từ năm 1995 của Brendan Eich. Trong máy ảo JS đầu tiên, giá trị biến được biểu diễn bằng 32-bit gồm Type Tag và Payload. Type Tag 000 biểu thị Object, trong khi null là con trỏ rỗng có địa chỉ 0x00 nên máy ảo nhận nhầm tag là Object. Lỗi này không bao giờ được sửa vì nguyên tắc Don't Break the Web: hàng triệu website và thư viện sản xuất từ 1995 đến nay đã viết logic phòng thủ dựa trên hành vi này; nếu TC39 sửa đổi sẽ gây vỡ ứng dụng diện rộng."

🎓 Câu hỏi 2: Khi nào toán tử instanceof thất bại hoặc cho kết quả không chính xác ?

Cách trả lời Top-Down chuẩn Senior :

"instanceof thất bại trong 3 trường hợp chính :

  1. Môi trường Cross-Realm (Iframe, Micro-frontends, Web Workers) : Mỗi Realm có một Global Object và bộ Constructors riêng trong bộ nhớ. Mảng tạo từ iframe có prototype trỏ tới iframe.contentWindow.Array.prototype, không cùng tham chiếu với window.Array.prototype, khiến arr instanceof Array trả về false.
  2. Primitive Literals : 'str' instanceof String là false vì primitives không có prototype chain trực tiếp.
  3. Prototype Mutation : Khi dùng Object.setPrototypeOf() hoặc ghi đè Symbol.hasInstance, logic của instanceof có thể bị đánh lừa."
🎓 Câu hỏi 3: Làm thế nào để viết hàm isPlainObject(val) chuẩn xác như trong Redux hoặc Lodash ?

Cách trả lời Top-Down chuẩn Senior :

"Một Plain Object là đối tượng được tạo bởi {}, new Object(), hoặc Object.create(null). Kiểm tra bằng typeof val === 'object' là không đủ vì nó sẽ nhận nhầm cả Array, Date, Regex và null. Ta cần kết hợp 2 điều kiện :

isPlainObject Implementation 
function isPlainObject(val) {
  if (Object.prototype.toString.call(val) !== '[object Object]') return false;
  const proto = Object.getPrototypeOf(val);
  // Hỗ trợ Object.create(null) hoặc prototype trỏ thẳng Object.prototype
  return proto === null || proto === Object.prototype;
}
