1. Layout Thrashing (Forced Synchronous Layout) là gì ?

Bình thường, trình duyệt rất thông minh: nó sẽ gom nhiều thao tác sửa đổi DOM (Writes) vào hàng đợi và chỉ tính toán lại Layout một lần duy nhất vào cuối khung hình (Frame).
Tuy nhiên, nếu bạn vừa sửa DOM (Write) rồi ngay lập tức đọc thông số hình học (Read) trong vòng lặp, trình duyệt bị ép buộc phải tạm dừng JavaScript và tính toán lại Layout ngay lập tức để trả về con số chính xác. Quá trình này lặp đi lặp lại $N$ lần được gọi là Layout Thrashing.

JavaScript — Cạm bẫy Layout Thrashing (BAD vs GOOD) 
// ❌ BAD: Đan xen Read (offsetWidth) và Write (width) → N lần Reflow!
for (let i = 0; i < elements.length; i++) {
  const width = elements[i].offsetWidth;     // READ (Forced Reflow!)
  elements[i].style.width = `${width + 10}px`; // WRITE (Làm bẩn Layout)
}

// ✅ GOOD: Đọc hết toàn bộ trước (Batch Reads), sau đó mới Ghi (Batch Writes) → 1 lần Reflow!
const newWidths = elements.map(el => el.offsetWidth + 10); // Batch READS
elements.forEach((el, i) => {
  el.style.width = `${newWidths[i]}px`;                     // Batch WRITES
});

2. Danh sách các thuộc tính & phương thức ép buộc Reflow

Bất kỳ khi nào bạn truy cập các thuộc tính sau sau một thao tác sửa đổi DOM, trình duyệt bắt buộc phải chạy Reflow ngay lập tức :

Nhóm APIThuộc tính / Phương thứcMẹo tránh lỗi
Kích thước Box offsetWidth, offsetHeight, clientWidth, clientHeight Lưu vào biến (cache) nếu kích thước không đổi
Tọa độ & Vị trí offsetLeft, offsetTop, clientLeft, clientTop Đọc trước khi sửa đổi CSS
Cuộn trang scrollWidth, scrollHeight, scrollLeft, scrollTop Dùng IntersectionObserver thay vì đo scrollTop liên tục
Đo đạc hình học getBoundingClientRect(), getComputedStyle() Gom vào requestAnimationFrame

3. Gom cụm DOM với DocumentFragment

Khi cần thêm 1,000 phần tử vào danh sách, nếu bạn gọi parentElement.appendChild(node) 1,000 lần, trình duyệt sẽ phải cập nhật DOM 1,000 lần.
Giải pháp : Sử dụng DocumentFragment — một nút DOM nhẹ nằm hoàn toàn trong bộ nhớ RAM, không thuộc cây hiển thị :

JavaScript — Tối ưu chèn 1,000 phần tử với DocumentFragment 
const fragment = document.createDocumentFragment();

for (let i = 0; i < 1000; i++) {
  const item = document.createElement('li');
  item.textContent = `Sản phẩm ${i}`;
  fragment.appendChild(item); // Thao tác 100% trong RAM, không gây Reflow
}

document.getElementById('list').appendChild(fragment); // Chỉ 1 lần gắn vào DOM duy nhất!

4. Tối ưu hiện đại: contain & content-visibility

  • contain: content hoặc contain: layout size style : Cô lập cây DOM con khỏi phần còn lại của trang web. Khi có mutation bên trong thẻ này, trình duyệt chỉ tính toán Reflow cục bộ trong thẻ đó mà không lan sang toàn bộ tài liệu.
  • content-visibility: auto : Tự động bỏ qua việc render (bỏ qua cả Layout lẫn Paint) cho các phần tử nằm ngoài màn hình nhìn thấy (Off-screen) cho đến khi người dùng cuộn tới — tăng tốc độ nạp trang ban đầu lên gấp 5-10 lần !
