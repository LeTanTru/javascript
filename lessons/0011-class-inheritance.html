Bài 11 · Prototypal Inheritance vs ES6 Classes, super & Private Fields (#field)

Giải phẫu bản chất Syntactic Sugar của ES6 Classes, lý giải tại sao bắt buộc phải gọi super() trước khi dùng this trong Subclass, và cơ chế bảo mật cấp ngôn ngữ của Private Fields (#field).

⏳ ~18 phút · 🎯 Mục tiêu: Nắm vững mô hình kế thừa kép trong ES6 Class (Instance Chain + Static Chain), hiểu sâu cơ chế cấp phát this của Subclass và phân biệt các phương pháp đóng gói Private State.

🌉 Cầu nối từ Bài 10

Ở Bài 10, chúng ta đã mổ xẻ 4 bước của toán tử new và cách Object.create() liên kết các prototype object. Trong lịch sử JavaScript (trước ES6), để thực hiện kế thừa giữa hai hàm constructor, lập trình viên phải sử dụng mô hình phức tạp mang tên Parasitic Combination Inheritance.

ES6 mang đến cú pháp class, extends và super khiến JavaScript trông giống hệt Java hay C++. Nhưng liệu đây có phải là Classical Inheritance thật sự không ? Bản chất của từ khóa super dưới góc nhìn ECMAScript là gì ?

1. ES6 Class có thực sự là một mô hình OOP mới không ?

Câu trả lời thẳng thắn : KHÔNG. ES6 Class bản chất 100% là Syntactic Sugar (Đường mật cú pháp) phủ lên trên nền tảng Prototypal Inheritance và Prototype Chain sẵn có của JavaScript.

Tuy nhiên, Class không chỉ là cú pháp viết tắt; Engine áp dụng một số quy tắc bảo vệ nghiêm ngặt mà hàm thông thường không có :

Tiêu chí so sánh Function Constructor (ES5) ES6 Class
Gọi không có từ khóa new Được phép (nhưng làm ô nhiễm window trong non-strict mode) BỊ CẤM → Ném TypeError: Class constructor cannot be invoked without 'new'

2. Cơ chế Subclassing: Tại sao bắt buộc phải gọi super() trước this ?

Đây là câu hỏi phỏng vấn Senior Frontend xuất hiện với tần suất cực cao :

⚠ Sự đảo ngược thứ tự cấp phát 'this' giữa ES5 và ES6

Trong kế thừa ES5 (Subclass tạo this trước) :

  • Hàm Child được gọi → Toán tử new tạo ra một object rỗng mới làm this của Child.
  • Sau đó Child gọi Parent.call(this, ...) để mượn cha gán thêm thuộc tính vào this đã có sẵn đó.

Trong kế thừa ES6 (Base Class tạo this trước) :

  • Khi khởi tạo một Subclass (class có extends), JavaScript Engine KHÔNG cấp phát vùng nhớ this cho Subclass ban đầu ! Lúc này this đang ở trạng thái Uninitialized.
  • Hàm super(...args) chịu trách nhiệm kích hoạt Constructor của lớp cha (Base Class) để lớp cha tạo ra instance và cấp phát ô nhớ cho this.
  • Sau khi super() chạy xong, Engine mới gán tham chiếu this đó về cho Subclass.
  • Hệ quả : Nếu bạn truy cập this trước khi gọi super(), Engine sẽ lập tức ném ngoại lệ ReferenceError: Must call super constructor in derived class before accessing 'this' !
JavaScript — Thí nghiệm Subclass Constructor 
class Parent {
  constructor(name) { this.name = name; }
}

class Child extends Parent {
  constructor(name, role) {
    // this.role = role; // → ReferenceError ! 'this' chưa được khởi tạo !
    super(name);         // → Khởi tạo 'this' từ Parent
    this.role = role;    // → Bây giờ mới được dùng 'this' an toàn
  }
}

3. Kế thừa kép trong ES6 Class (Double Prototype Chain)

Khi dùng class Child extends Parent, JavaScript Engine tự động thiết lập 2 chuỗi prototype độc lập song song :

  1. Instance Prototype Chain (Kế thừa phương thức thực thể) :
    Child.prototype.[[Prototype]] === Parent.prototype
    Giúp các đối tượng childInstance truy cập được các phương thức định nghĩa trong Parent.prototype.
  2. Constructor Prototype Chain (Kế thừa phương thức tĩnh - Static Methods) :
    Child.[[Prototype]] === Parent
    Bản thân hàm Child kế thừa trực tiếp từ hàm Parent. Nhờ đó, bất kỳ phương thức tĩnh (static method) nào trên Parent đều có thể gọi trực tiếp từ Child.myStaticMethod() !

4. ES2022 Private Fields (#field): Bảo mật tuyệt đối cấp ngôn ngữ

Trong lịch sử, lập trình viên thường dùng tiền tố _name (chỉ là quy ước cộng đồng, vẫn đọc được từ bên ngoài) hoặc dùng Closures (tốn bộ nhớ Context Object trên Heap). Từ ES2022, JavaScript chính thức chuẩn hóa Private Fields (#field) :

JavaScript — ES2022 Private Fields 
class BankAccount {
  #balance = 0; // Private field đích thực cấp ngôn ngữ

  constructor(initial) {
    this.#balance = initial;
  }

  deposit(amount) {
    this.#balance += amount;
    return this.#balance;
  }
}

const acc = new BankAccount(500);
acc.deposit(200);

// Thử truy cập bằng mọi cách:
console.log(acc.#balance);   // → SyntaxError ngay tại thời điểm biên dịch !
console.log(acc["#balance"]); // → undefined !
console.log(Object.keys(acc)); // → [] (Vô hình hoàn toàn trước reflection)
💡 Cơ chế V8 PrivateBrand / PrivateIdentifier

Private Fields không được lưu trữ như các property thông thường trên đối tượng trong Memory Heap. V8 sử dụng cơ chế gọi là PrivateBrand: kiểm tra xem đối tượng có mang con dấu thương hiệu của Class hay không tại bytecode level. Điều này giúp Private Fields đạt được tính Hard Private (Bảo mật tuyệt đối, không có bất kỳ API nào có thể hack vào đọc lén).

5. Góc phỏng vấn Senior Frontend

🎓 Q1: Tại sao trong constructor của một Subclass trong ES6, chúng ta bắt buộc phải gọi super() trước khi chạm vào this ?

Trả lời Top-Down chuẩn Senior :

"Trong đặc tả ES6, cơ chế cấp phát bộ nhớ của Subclass bị đảo ngược so với ES5: `this` không do Subclass khởi tạo mà do Base Class (lớp cha) khởi tạo thông qua lệnh `super()`. Trước khi `super()` hoàn thành, biến liên kết `this` trong Derived Constructor vẫn nằm trong trạng thái Uninitialized (tương tự TDZ). Mọi truy cập vào `this` trước thời điểm này sẽ ném `ReferenceError` để đảm bảo instance của cha được dựng hoàn chỉnh trước khi con mở rộng."

🎓 Q2: Sự khác biệt giữa Class Fields thông thường (`x = 1`) và Methods khai báo trong class (`foo() {}`) về mặt vị trí lưu trữ bộ nhớ là gì ?

Trả lời Top-Down chuẩn Senior :

"`Class Fields` (ví dụ `x = 1` hoặc arrow functions `handleClick = () => {}`) được gán trực tiếp lên từng **Instance đối tượng** trong mỗi lần gọi `new`, nghĩa là mỗi instance đều tốn thêm ô nhớ riêng. Ngược lại, các method thông thường (`foo() {}`) được định nghĩa duy nhất một lần trên **`Class.prototype`** và được chia sẻ dùng chung cho tất cả các instances thông qua Prototype Chain, tối ưu hóa bộ nhớ vượt trội."
