Primitive vs Reference Types & Mô hình bộ nhớ Call Stack vs Heap

Giải mã cơ chế cấp phát bộ nhớ của V8 Engine, hiểu tận gốc Pass-by-value vs Pass-by-sharing và tự tin chinh phục các câu hỏi phỏng vấn kinh điển.

⏱ ~15 phút · 🎯 Mục tiêu: Vẽ được sơ đồ phân bổ ô nhớ Call Stack & Memory Heap, phân biệt rạch ròi Mutation vs Reassignment, và vượt qua 100% câu hỏi bẫy về Copy/Tham chiếu.

🌉 Bắc cầu từ câu hỏi tư duy ở Bài 00

Ở cuối Bài 00, chúng ta đã bắt gặp một hiện tượng kỳ lạ:

JavaScript 
let a = { name: "Alice" };
let b = a;
a.name = "Bob";
console.log(b.name); // -> In ra "Bob" (b bị thay đổi theo!)

let x = 10;
let y = x;
x = 20;
console.log(y);      // -> In ra 10 (y hoàn toàn độc lập!)

Tại sao cùng là phép gán bằng =, nhưng Object thì bị kéo theo (mutated), còn số nguyên thì hoàn toàn độc lập? Câu trả lời nằm ở mô hình tổ chức bộ nhớ bên trong JavaScript Engine.

1. 7 Kiểu Primitive vs Reference Types (ECMA-262)

Theo tài liệu đặc tả chuẩn ECMA-262 (ECMAScript Language Types), hệ thống kiểu của JavaScript được chia làm hai nhóm đối lập hoàn toàn:

Đặc điểm Primitive Types (Kiểu nguyên thủy) Reference Types (Kiểu tham chiếu)
Danh sách kiểu string, number, bigint, boolean, undefined, symbol, null (7 kiểu) Object (và các biến thể: Array, Function, Date, RegExp, Map, Set)
Tính bất biến (Immutability) Bất biến (Immutable) — Không thể chỉnh sửa trực tiếp giá trị trong ô nhớ (mọi thao tác chuỗi/số đều tạo ra giá trị mới) Đột biến được (Mutable) — Có thể thêm, xóa, sửa thuộc tính trực tiếp trên đối tượng
Nơi lưu trữ trong V8 Lưu trữ trực tiếp trên Call Stack (giá trị cố định, kích thước xác định trước) Cấp phát động trên Memory Heap (kích thước linh hoạt, có thể phình to)
Phép gán biến (`=`) Sao chép toàn bộ giá trị thực tế (Value copy) Sao chép con trỏ địa chỉ bộ nhớ (Reference pointer)
💡 Vì sao Primitive lại là Immutable (Bất biến)?

Nhiều người lầm tưởng khai báo let str = "hello"; str = "world"; là biến đổi chuỗi. Thực tế không phải: chuỗi "hello" trong ô nhớ cũ vẫn giữ nguyên, biến str chỉ được trỏ tới một ô nhớ mới chứa giá trị "world". Bạn không thể làm str[0] = "H" để biến chữ thường thành chữ hoa — JavaScript sẽ âm thầm bỏ qua (hoặc ném lỗi trong strict mode).

2. Kiến trúc bộ nhớ V8: Call Stack vs Memory Heap

JavaScript Engine (như Google V8 trong Chrome và Node.js) chia không gian bộ nhớ thành 2 vùng chính:

  • Call Stack: Vùng nhớ có cấu trúc ngăn xếp (LIFO), truy xuất siêu tốc. Nơi lưu trữ Execution Contexts, các frame hàm đang chạy, và các biến primitive có kích thước cố định.
  • Memory Heap: Vùng nhớ phi cấu trúc (Unstructured memory pool), nơi cấp phát bộ nhớ động cho các đối tượng (Objects, Arrays, Closures). Kích thước ô nhớ có thể co giãn linh hoạt trong quá trình chạy.
Sơ đồ mô phỏng cấp phát bộ nhớ trong V8 Engine 
   CALL STACK (Execution Frame)                  MEMORY HEAP (Dynamic Pool)
 ┌──────────────┬──────────────────┐          ┌─────────────────────────────┐
 │ Biến         │ Giá trị lưu trữ  │          │ Ô nhớ thực tế & Dữ liệu     │
 ├──────────────┼──────────────────┤          ├─────────────────────────────┤
 │ x            │ 10               │          │                             │
 │ y            │ 10               │          │                             │
 │ a            │ 0x7FFF01 ────────┼─────────►│ Địa chỉ: 0x7FFF01           │
 │ b            │ 0x7FFF01 ────────┼─────────►│ { name: "Bob" }             │
 └──────────────┴──────────────────┘          └─────────────────────────────┘
  * Biến `b = a` chỉ sao chép con trỏ 0x7FFF01. Cả `a` và `b` cùng trỏ chung 1 Object!

3. JavaScript là Pass-by-value hay Pass-by-reference?

Đây là câu hỏi xuất hiện trong 90% các buổi phỏng vấn kỹ thuật từ mức Middle đến Senior. Nhiều lập trình viên trả lời nhầm: "Primitive là pass-by-value, còn Object là pass-by-reference".

⚠️ Câu trả lời chính xác: JavaScript 100% LUÔN LUÔN là Pass-by-value!

Trong thuật ngữ khoa học máy tính chuẩn mực, JavaScript sử dụng cơ chế gọi là Pass-by-sharing (hay Call-by-sharing). Bản chất của nó vẫn là Pass-by-value:

  • Với Primitive: Giá trị được truyền là nội dung thực tế (con số, chuỗi ký tự).
  • Với Object: Giá trị được truyền là địa chỉ con trỏ tham chiếu (Memory Address Reference). Giá trị con trỏ này được copy nguyên xi vào tham số hàm!

Hãy xem ví dụ kinh điển chứng minh JavaScript không thể là Pass-by-reference thật sự:

JavaScript — Minh chứng Pass-by-sharing 
function updateUser(user) {
  // 1. Đột biến thuộc tính (Mutation): Ảnh hưởng ra ngoài vì chung địa chỉ
  user.name = "Charlie";

  // 2. Gán lại biến (Reassignment): user trỏ sang một ô nhớ hoàn toàn mới
  user = { name: "David" };
}

const me = { name: "Alice" };
updateUser(me);

console.log(me.name); // -> In ra "Charlie", KHÔNG PHẢI "David"!
💡 Phân tích sâu: Tại sao me.name không trở thành "David"?

Nếu JavaScript là Pass-by-reference thực thụ (như C++ với con trỏ User*& hoặc C# với từ khóa ref), khi tham số user bị gán lại bằng { name: "David" }, biến me ở scope ngoài cũng bắt buộc phải trỏ theo đối tượng mới.
Nhưng trong JavaScript, tham số user chỉ nhận một bản sao giá trị con trỏ. Khi ta gán lại user = ..., ta chỉ đổi hướng trỏ của biến cục bộ đó, hoàn toàn không làm lay chuyển biến me ban đầu!

4. Đột biến (Mutation) vs Gán lại (Reassignment) & Bẫy Shallow Copy

Khi làm việc với state trong các thư viện hiện đại (như React Redux, Zustand), nguyên tắc số 1 là Immutability (Bất biến). Để tránh mutate dữ liệu gốc, lập trình viên thường copy object.

Bẫy Shallow Copy với Spread Operator (`{ ...obj }`)

JavaScript — Bẫy nông với Nested Objects 
const state = {
  user: { name: "Nam", city: "Hanoi" },
  status: "active"
};

// Shallow Copy: Chỉ clone thuộc tính cấp 1
const nextState = { ...state };
nextState.status = "offline";           // An toàn: status là primitive

// BẪY: user là nested object, nextState.user vẫn trỏ chung ô nhớ với state.user!
nextState.user.city = "Saigon";
console.log(state.user.city);           // -> In ra "Saigon"! State cũ đã bị mutate!

Giải pháp Deep Copy hiện đại: Native `structuredClone`

Trước đây, lập trình viên thường dùng JSON.parse(JSON.stringify(obj)) nhưng giải pháp này làm mất Date (bị ép thành string), mất undefined, Symbol, không sao chép được Map/Set và gãy hoàn toàn nếu gặp tham chiếu vòng tròn (Circular Reference).

Từ Node.js 17 và mọi trình duyệt hiện đại (2022+), hàm native structuredClone() đã trở thành tiêu chuẩn vàng:

JavaScript — Deep Clone an toàn tuyệt đối 
const deepCopied = structuredClone(state);
deepCopied.user.city = "Da Nang";

console.log(state.user.city); // -> Vẫn là "Hanoi"! Hoàn toàn bất biến.
🎙️ Góc phỏng vấn Senior: Cách trả lời chuẩn Top-Down

Câu hỏi 1: "Giải thích cơ chế truyền tham số của hàm trong JavaScript: Pass-by-value hay Pass-by-reference?"

👉 Câu trả lời Senior (Phương pháp Top-Down):
"JavaScript hoàn toàn là Pass-by-value trong mọi trường hợp. Tuy nhiên, với kiểu dữ liệu đối tượng (Reference types), giá trị được truyền đi chính là địa chỉ bộ nhớ (Memory pointer) của đối tượng đó trên Heap — thuật ngữ chuẩn khoa học máy tính gọi là Pass-by-sharing.
Hệ quả là: Ta có thể biến đổi các thuộc tính bên trong đối tượng (Mutation) và sự thay đổi này sẽ phản chiếu ra bên ngoài. Nhưng nếu ta gán lại (Reassign) biến tham số sang một đối tượng hoàn toàn mới, biến ban đầu ở phạm vi gọi hàm hoàn toàn không bị ảnh hưởng."

Câu hỏi 2: "Tại sao trong JavaScript `typeof null` lại trả về `'object'`? Có phải null là một Object không?"

👉 Câu trả lời Senior:
"Không, null hoàn toàn là một Primitive Type theo đặc tả ECMA-262.
Việc typeof null === 'object' là một bug lịch sử từ phiên bản đầu tiên của JavaScript (năm 1995). Trong bộ engine C ban đầu của Brendan Eich, các giá trị trong JS được gắn tag loại kiểu bằng 32-bit: tag 000 biểu thị kiểu Object. Vì giá trị con trỏ null trong C là con trỏ rỗng (toàn bộ bit đều bằng 0, dẫn tới tag type là 000), hàm typeof đã nhận diện nhầm nó thành Object. Đề xuất sửa lỗi này ở ECMAScript 6 đã bị từ chối vì nó sẽ làm phá vỡ (breaking changes) hàng triệu trang web đang tồn tại."

6. Câu hỏi tư duy (Bắc cầu sang Bài 02)

Chúng ta vừa khẳng định: Kiểu dữ liệu Primitive (như string, number) chỉ là các giá trị thô lưu trên Call Stack, hoàn toàn không phải Object và không thể chứa thuộc tính/phương thức.

Vậy tại sao trong thực tế bạn vẫn có thể viết:

JavaScript 
const str = "hello";
console.log(str.toUpperCase());  // -> Gọi được phương thức như Object?!

const num = 42;
console.log(num.toFixed(2));      // -> Gọi được toFixed?!

console.log([] + {});            // -> Ra "[object Object]"?!
console.log([] - 1);             // -> Ra -1?!
