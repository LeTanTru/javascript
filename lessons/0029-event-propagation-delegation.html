🌉 Cầu nối từ Bài 28

Ở Bài 28, bạn đã biết cách Browser dựng cây DOM và Render Tree. Khi trang web đã hiển thị, người dùng bắt đầu tương tác (click, scroll, keypress). Để các tương tác này được xử lý hiệu quả và có tổ chức, DOM áp dụng mô hình Event Propagation (Lan truyền sự kiện).

1. Mô hình 3 pha lan truyền sự kiện (W3C DOM Event Flow)

Khi bạn click vào một thẻ <button> nằm sâu trong trang web, sự kiện không xảy ra ngay lập tức tại button đó mà trải qua một hành trình 3 pha :

  1. Phase 1: Capturing Phase (Pha Bắt giữ) : Sự kiện bắt đầu từ đỉnh cây DOM (Window → Document → <html> → <body> → các thẻ cha) đi dần xuống trước khi chạm đến target.
  2. Phase 2: Target Phase (Pha Đích) : Sự kiện đến chính xác phần tử mục tiêu (event.target).
  3. Phase 3: Bubbling Phase (Pha Nổi bọt) : Sự kiện nổi ngược từ phần tử mục tiêu trở lên đỉnh cây DOM (Window). Đây là pha mặc định mà hầu hết các listener hoạt động.
JavaScript — Cú pháp đăng ký Capturing vs Bubbling 
// Mặc định: Lắng nghe ở pha BUBBLING (tham số thứ 3 là false)
element.addEventListener('click', handler);

// Lắng nghe ở pha CAPTURING (truyền true hoặc { capture: true })
element.addEventListener('click', handler, true);
element.addEventListener('click', handler, { capture: true });

2. stopPropagation() vs stopImmediatePropagation() vs preventDefault()

Phương thứcTác dụngCác listener khác trên cùng node ?Hành vi mặc định của Browser ?
e.stopPropagation() Dừng sự kiện lan truyền lên/xuống các node cha/con. Vẫn tiếp tục chạy Không bị chặn
e.stopImmediatePropagation() Dừng lan truyền VÀ chặn luôn các listener còn lại trên cùng node. Bị hủy bỏ ngay Không bị chặn
e.preventDefault() Chặn hành vi mặc định (chặn mở link <a>, submit form). Vẫn chạy bình thường Bị chặn hoàn toàn

3. Event Delegation (Ủy quyền sự kiện)

Giả sử bạn có danh sách 1,000 dòng sản phẩm. Thay vì gắn 1,000 hàm lắng nghe vào từng thẻ <li> (gây tốn RAM và rò rỉ bộ nhớ), bạn chỉ gắn 1 listener duy nhất lên thẻ cha <ul> và tận dụng Event Bubbling :

JavaScript — Event Delegation chuẩn mực với Element.closest() 
const todoList = document.getElementById('todo-list');

todoList.addEventListener('click', (event) => {
  // Tìm phần tử button xóa gần nhất từ event.target
  const deleteBtn = event.target.closest('.delete-btn');
  if (deleteBtn && todoList.contains(deleteBtn)) {
    const itemId = deleteBtn.dataset.id;
    deleteTodoItem(itemId);
  }
});

4. Tối ưu cuộn trang 60fps với { passive: true }

Khi người dùng vuốt màn hình cảm ứng (touch) hoặc lăn chuột (wheel), trình duyệt phải đợi JavaScript thực thi listener xong để xem bạn có gọi e.preventDefault() để chặn cuộn hay không. Sự chậm trễ này gây ra hiện tượng Scroll Jank (khựng khung hình).

🚀 { passive: true } giải phóng UI Thread

Bằng cách truyền { passive: true }, bạn cam kết với trình duyệt: "Tôi sẽ không bao giờ gọi preventDefault() trong hàm này". Trình duyệt sẽ cho phép luồng GPU Compositor cuộn trang ngay lập tức ở 60fps mà không cần chờ đợi JavaScript !
