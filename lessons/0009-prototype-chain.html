Bài 09 · Prototype Chain: Phân biệt prototype vs __proto__ vs [[Prototype]]

Phá vỡ sự nhầm lẫn kinh điển nhất trong OOP của JavaScript: phân định rạch ròi giữa khuôn mẫu của hàm khởi tạo, accessor property và internal slot kế thừa theo chuẩn ECMAScript.

⏳ ~18 phút · 🎯 Mục tiêu: Phân biệt chính xác 3 khái niệm prototype, nắm vững cơ chế duyệt chuỗi Prototype Chain, Property Shadowing và kỹ thuật Dictionary thuần với Object.create(null).

🌉 Cầu nối từ Module 02

Ở Module 02, chúng ta đã nắm trọn cách JavaScript phân giải biến qua Scope Chain (Singly Linked List của các Lexical Environments). Nhưng khi chúng ta truy cập thuộc tính của một đối tượng (ví dụ user.toString()), JavaScript không tìm kiếm trên Scope Chain mà tra cứu trên một chuỗi hoàn toàn khác: Prototype Chain.

JavaScript là một ngôn ngữ hướng đối tượng dựa trên nguyên mẫu (Prototype-based Object-Oriented Language). Hiểu rõ Prototype Chain là chìa khóa để giải mã từ khóa new, class, cơ chế kế thừa và tối ưu hóa bộ nhớ cấp cao.

1. Giải phẫu 3 khái niệm Prototype: Bộ ba dễ nhầm lẫn nhất

Ký hiệu / Thuộc tính Bản chất kỹ thuật theo ECMA-262 Tồn tại ở đâu ? Mục đích sử dụng
[[Prototype]] Internal Slot ẩn (Trường nội bộ của Engine). Không thể truy cập trực tiếp bằng cú pháp dấu chấm thông thường. Mọi Object trong JavaScript (trừ Object.create(null)). Lưu trữ tham chiếu trực tiếp đến đối tượng cha mà object này kế thừa.
__proto__ Accessor Property (gồm hàm getter và setter) được định nghĩa trên Object.prototype. Kế thừa từ Object.prototype xuống các đối tượng con. Cho phép lập trình viên đọc/ghi vào [[Prototype]] (Đã bị coi là deprecated trong chuẩn hiện đại).
prototype Thuộc tính thông thường (Object property) chỉ trỏ tới một object đóng vai trò "khuôn mẫu". CHỈ tồn tại trên Function (Constructor Functions, Class). Không có trên Arrow Functions hay instance ! Được dùng để gán làm [[Prototype]] cho các instance tạo ra bởi lệnh new Fn().
⚠ Bằng chứng Arrow Function & Instance không có thuộc tính prototype
JavaScript — Kiểm tra thuộc tính prototype 
function Car(brand) { this.brand = brand; }
const arrow = () => {};
const myCar = new Car("Toyota");

console.log(typeof Car.prototype);   // → "object" (Có prototype)
console.log(arrow.prototype);        // → undefined (Arrow function KHÔNG CÓ prototype !)
console.log(myCar.prototype);        // → undefined (Instance KHÔNG CÓ thuộc tính prototype !)

// Truy cập [[Prototype]] của instance chuẩn mực:
console.log(Object.getPrototypeOf(myCar) === Car.prototype); // → true !

2. Cơ chế duyệt chuỗi Prototype Chain & Property Shadowing

Khi bạn thực hiện thao tác đọc một thuộc tính trên đối tượng (obj.property), JavaScript Engine thực hiện thuật toán tìm kiếm tuyến tính :

  1. Kiểm tra xem property có phải là Own Property (thuộc tính của chính bản thân obj) hay không bằng Object.hasOwn(obj, "property"). Nếu có → Trả về giá trị ngay.
  2. Nếu không có, Engine lần theo con trỏ [[Prototype]] để nhảy lên đối tượng cha.
  3. Lặp lại bước 1 và 2 dọc theo chuỗi kế thừa cho đến khi chạm tới Object.prototype.
  4. Nếu tại Object.prototype vẫn không tìm thấy, Engine kiểm tra [[Prototype]] của nó: giá trị này là null (đỉnh của chuỗi). Engine dừng lại và trả về undefined.
💡 Hiện tượng Property Shadowing (Che khuất thuộc tính)

Khi ta gán giá trị cho một thuộc tính (child.title = "New Title"), theo quy tắc thông thường, JavaScript sẽ tạo ra một Own Property mới trực tiếp trên child, che khuất thuộc tính cùng tên của Prototype cha mà không hề làm thay đổi Prototype gốc :

JavaScript 
const parent = { role: "Admin" };
const child = Object.create(parent);

console.log(child.role); // → "Admin" (Đọc từ parent)

child.role = "Member";  // Tạo own property trên child
console.log(child.role);  // → "Member" (Shadowing)
console.log(parent.role); // → "Admin" (Parent vẫn nguyên vẹn !)

3. Chuẩn thao tác Prototype hiện đại & Bí mật Object.create(null)

3.1. Tại sao KHÔNG BAO GIỜ nên dùng __proto__ hay Object.setPrototypeOf() trong Production ?

  • __proto__ là di sản lỗi thời : Nó chỉ là một phụ lục tương thích ngược (Annex B của đặc tả). Sử dụng nó làm chậm code và không được đảm bảo trên mọi môi trường JS phi trình duyệt.
  • Object.setPrototypeOf() làm sụp đổ tối ưu hóa của V8 : JavaScript Engine tối ưu hóa việc truy cập thuộc tính thông qua Hidden Classes (Shapes) và Inline Caching. Khi bạn đột biến prototype của một đối tượng đang chạy, V8 lập tức giải tối ưu hóa (De-optimization), khiến tốc độ truy xuất thuộc tính chậm đi hàng chục lần !
  • Giải pháp chuẩn Senior : Luôn thiết lập prototype ngay tại thời điểm khởi tạo bằng Object.create(proto) hoặc cú pháp class / constructor.

3.2. Ứng dụng đỉnh cao: Dictionary sạch tuyệt đối với Object.create(null)

Một Object thông thường ({}) luôn kế thừa từ Object.prototype, do đó nó tiềm ẩn nguy cơ bảo mật Prototype Pollution hoặc lỗi khi dữ liệu vô tình trùng tên với các phương thức có sẵn như toString, valueOf, constructor.

Để tạo một bảng tra cứu (Dictionary / Hash Map) thuần túy không chứa bất kỳ thuộc tính kế thừa nào :

JavaScript — Pure Dictionary 
const map = Object.create(null);

console.log(Object.getPrototypeOf(map)); // → null !
console.log(map.toString);               // → undefined (Không hề có prototype)

// An toàn tuyệt đối làm Dictionary:
map["toString"] = "Giá trị của tôi";
console.log(map.toString);               // → "Giá trị của tôi" (Không lo bị override method hệ thống)

4. Góc phỏng vấn Senior Frontend

🎓 Q1: Phân biệt rõ ràng giữa `prototype` và `__proto__` bằng một câu trả lời súc tích ?

Trả lời Top-Down chuẩn Senior :

"`prototype` là thuộc tính chỉ có trên các Constructor Function và Class, đóng vai trò là bản thiết kế mẫu để gán vào các instance con khi được tạo ra bởi lệnh `new`. Trong khi đó, `__proto__` (hoặc chuẩn hơn là internal slot `[[Prototype]]`) là con trỏ tham chiếu nằm trên mọi Object instance, trỏ ngược về prototype của cha mà nó kế thừa. Tóm lại: `instance.__proto__ === Constructor.prototype`."

🎓 Q2: Phân biệt toán tử `in` và phương thức `Object.hasOwn()` ?

Trả lời Top-Down chuẩn Senior :

"`Object.hasOwn(obj, prop)` (chuẩn ES2022 thay thế cho `obj.hasOwnProperty`) chỉ kiểm tra xem thuộc tính đó có phải là Own Property của chính đối tượng hay không, bỏ qua hoàn toàn Prototype Chain. Ngược lại, toán tử `'prop' in obj` sẽ kiểm tra toàn bộ Prototype Chain từ đối tượng hiện tại ngược lên tới đỉnh `Object.prototype`."
