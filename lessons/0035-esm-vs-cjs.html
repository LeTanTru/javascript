1. CommonJS (CJS): Module Wrapper & Value Copy

Khi Node.js thực thi một file CJS, nó tự động bọc toàn bộ mã nguồn của bạn bên trong một hàm IIFE gọi là Module Wrapper:

JavaScript — CJS Module Wrapper (Node.js Internal) 
(function (exports, require, module, __filename, __dirname) {
  // Code của bạn nằm tại đây
  let count = 0;
  function increment() { count++; }
  module.exports = { count, increment };
});
💡 Đặc điểm sống còn của CommonJS
  • Runtime & Synchronous: require() là một hàm JavaScript bình thường, chạy tuần tự đồng bộ tại runtime (chặn I/O file).
  • Value Copy (Sao chép giá trị): Khi module.exports = { count }, giá trị của count được copy tại thời điểm gán. Khi hàm increment() thay đổi biến count nội bộ, biến count bên file import không hề thay đổi!
  • Caching: Kết quả của module.exports được lưu vào require.cache. Các lần gọi require() tiếp theo chỉ trả về tham chiếu đã lưu trong cache.

2. ECMAScript Modules (ESM): 3 Giai đoạn & Live Bindings

Khác với CJS chạy tức thì, ESM hoạt động theo tiêu chuẩn chính thức của ECMAScript qua 3 giai đoạn độc lập (3-Phase Lifecycle):

Giai đoạn (Phase)Nhiệm vụĐặc điểm cốt lõi
1. Construction (Tải & Parse) Tìm tất cả file, tải mã nguồn và phân tích cú pháp tĩnh thành Module Record. Phân tích tĩnh (Static Analysis) trước khi chạy. Cho phép Rollup/Webpack thực hiện Tree-shaking loại bỏ dead-code.
2. Instantiation (Liên kết) Cấp phát ô nhớ cho các export và liên kết (wire-up) chúng với các import. Tạo ra Live Bindings (Con trỏ trỏ thẳng vào Module Environment Record). Chưa thực thi code!
3. Evaluation (Thực thi) Chạy code từ lá lên gốc trong Module Graph để điền giá trị thực tế vào các ô nhớ. Hỗ trợ Top-level await, dừng việc thực thi module cha cho đến khi module con giải quyết Promise xong.
JavaScript — Minh họa Live Bindings trong ESM 
// counter.mjs
export let count = 0;
export function increment() { count++; }

// main.mjs
import { count, increment } from './counter.mjs';
console.log(count); // 0
increment();
console.log(count); // 1 <-- TỰ ĐỘNG CẬP NHẬT nhờ Live Binding! (Không thể làm được trong CJS)

// count = 10; // TypeError: Assignment to constant variable (Import bindings là Read-Only bên ngoài)

3. Giải mã Phụ thuộc xoay vòng (Circular Dependencies)

Khi Module A import Module B, và Module B lại import ngược lại Module A:

Hệ thống ModuleCách xử lý Circular DependencyHành vi và Rủi ro Runtime
CommonJS (CJS) Node.js trả về exports object chưa hoàn thiện (Partial Exports) tại thời điểm vòng lặp bị phát hiện. Nếu Module B truy cập thuộc tính mà Module A chưa kịp gán, nó sẽ nhận giá trị undefined. Dễ gây bug TypeError: Cannot read properties of undefined.
ECMAScript Modules (ESM) Nhờ tách biệt giai đoạn Instantiation và Evaluation, các bindings đã được wire-up trước khi chạy code. Hàm (Function Declarations) được hoisted nên gọi an toàn. Nhưng nếu truy cập biến let/const trước khi dòng gán của nó chạy, sẽ ném lỗi ReferenceError (TDZ - Temporal Dead Zone).

4. Dual Package Hazard & Interoperability (CJS vs ESM)

Khi viết thư viện npm hỗ trợ cả hai hệ sinh thái, việc xuất bản cả CJS build (dist/index.cjs) và ESM build (dist/index.mjs) có thể gây ra hiện tượng Dual Package Hazard: Khi một ứng dụng vô tình import cả 2 bản, module sẽ bị nạp 2 lần trong bộ nhớ, dẫn đến 2 singleton instances độc lập (gãy cơ chế instanceof và state caching)!

JSON — Cấu hình exports field chuẩn trong package.json 
{
  "name": "my-awesome-lib",
  "type": "module",
  "exports": {
    "import": "./dist/index.js",
    "require": "./dist/index.cjs",
    "types": "./dist/index.d.ts"
  }
}
