Bài 06 · Hoisting, Temporal Dead Zone (TDZ) & Sự khác biệt var vs let vs const

Phá vỡ lầm tưởng "let/const không bị hoisting", giải mã 3 bước của vòng đời biến (Declaration → Initialization → Assignment) và bản chất vùng chết tạm thời dưới góc nhìn Environment Record.

⏳ ~16 phút · 🎯 Mục tiêu: Chứng minh let/const có bị hoisting, giải thích nguyên nhân sâu xa của lỗi ReferenceError trong TDZ, và phân biệt rạch ròi cơ chế Block Scope trong vòng lặp for.

🌉 Cầu nối từ Bài 05

Ở Bài 05, chúng ta đã biết trong Creation Phase, biến var được đăng ký vào Variable Object và gán sẵn giá trị undefined. Nhờ đó, việc gọi biến trước dòng khai báo chỉ nhận về undefined.

Nhiều tài liệu nhập môn thường giải thích rằng: "let và const không bị hoisting". Đây là một hiểu lầm tai hại ! Cả let và const đều được Engine quét và đăng ký trong Creation Phase, nhưng chúng bị giam cầm trong một cơ chế bảo vệ nghiêm ngặt: Temporal Dead Zone (TDZ).

1. Bản chất Hoisting: Vòng đời 3 bước của một biến

Hoisting không phải là JavaScript Engine "cắt dán" code của bạn đưa lên đầu file. Mã nguồn vật lý không hề di chuyển. Hoisting thực chất là hệ quả của chu trình 2 pha (Creation Phase quét trước, Execution Phase chạy sau).

Một biến trong JavaScript trải qua 3 bước vòng đời riêng biệt :

  1. Declaration (Khai báo) : Đăng ký tên biến vào Environment Record của Execution Context.
  2. Initialization (Khởi tạo) : Cấp phát vùng nhớ vật lý và gán giá trị khởi tạo mặc định ban đầu.
  3. Assignment (Gán giá trị) : Gán giá trị cụ thể do lập trình viên chỉ định trong code.
Từ khóa Thời điểm Declaration Thời điểm Initialization Thời điểm Assignment Truy cập trước khi khai báo ?
var Creation Phase Creation Phase (gán ngay undefined) Execution Phase (dòng code gán) Trả về undefined
let Creation Phase Execution Phase (khi chạy tới dòng code) Execution Phase (dòng code gán) ReferenceError (dính TDZ)
const Creation Phase Execution Phase (khi chạy tới dòng code) Cùng lúc với Initialization ReferenceError (dính TDZ)

2. Temporal Dead Zone (TDZ) là gì ? Chứng minh let/const CÓ bị Hoisting

Temporal Dead Zone (Vùng chết tạm thời) là khoảng thời gian (từ lúc bắt đầu bước vào Block Scope cho đến khi dòng khai báo let hoặc const được thực thi). Trong khoảng này, biến đã được Declarative Environment Record nhận diện (đã Declare), nhưng chưa được cấp phát ô nhớ (Uninitialized).

⚠ Bằng chứng thép: Chứng minh let/const THỰC SỰ bị Hoisting

Nếu let không bị hoisting, JavaScript Engine sẽ tìm biến ngược lên scope cha bên ngoài. Nhưng hãy quan sát ví dụ sau :

JavaScript — Hiện tượng Shadowing trong TDZ 
let message = "Global scope";

function checkTDZ() {
  // Nếu let KHÔNG bị hoisting, dòng dưới sẽ in ra "Global scope" !
  console.log(message); // → ReferenceError: Cannot access 'message' before initialization !

  let message = "Local block";
}

checkTDZ();

Giải thích bản chất : Trong Creation Phase của hàm checkTDZ, Engine đã quét và phát hiện khai báo let message ở phạm vi cục bộ. Nó lập tức "khoá" định danh message trong TDZ của hàm này, ngăn không cho Scope Chain nhảy ra ngoài lấy "Global scope". Nếu không có Hoisting, lỗi này không bao giờ xảy ra !

⚠ Bẫy typeof trong TDZ: Phá vỡ sự an toàn tuyệt đối

Bình thường, typeof là toán tử an toàn nhất JS vì nó không bao giờ quăng lỗi kể cả khi biến chưa từng được khai báo :

JavaScript 
console.log(typeof undeclaredVariable); // → "undefined" (An toàn)

console.log(typeof tdzVariable);         // → ReferenceError !
let tdzVariable = 10;

TDZ là trường hợp duy nhất trong toàn bộ ngôn ngữ JavaScript có thể khiến toán tử typeof ném ra ngoại lệ ReferenceError.

3. Bảng so sánh var vs let vs const

Tiêu chí var (ES3) let (ES6) const (ES6)
Phạm vi (Scope) Function Scope (Rò rỉ khỏi if, for, {}) Block Scope (Đóng gói chặt trong {}) Block Scope (Đóng gói chặt trong {})
Hoisting & TDZ Hoisted → Gán sẵn undefined Hoisted → Dính TDZ Hoisted → Dính TDZ
Khai báo lại (Re-declare) Cho phép vô tư trong cùng scope Bị cấm (Ném SyntaxError ngay Creation Phase) Bị cấm (Ném SyntaxError ngay Creation Phase)
Gán lại (Re-assign) Cho phép gán lại bất kỳ lúc nào Cho phép gán lại bất kỳ lúc nào Bị cấm (Ném TypeError khi gán lại)
Global Object Pollution Tạo thuộc tính trên window (ví dụ: window.x) Không dính vào window (Declarative Environment) Không dính vào window (Declarative Environment)

4. Bẫy kinh điển: Vòng lặp for với var vs let

Đây là câu hỏi phỏng vấn xuất hiện với tần suất trên 90% ở mọi buổi phỏng vấn JavaScript :

JavaScript — So sánh vòng lặp for 
// TRƯỜNG HỢP 1: DÙNG VAR
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("var:", i), 100);
}
// → In ra: "var: 3", "var: 3", "var: 3"

// TRƯỜNG HỢP 2: DÙNG LET
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log("let:", j), 100);
}
// → In ra: "let: 0", "let: 1", "let: 2" !
💡 Tại sao lại có sự khác biệt kỳ diệu này ?

Với var : var có function scope nên chỉ tồn tại duy nhất một biến i cho toàn bộ vòng lặp. Khi 100ms sau callback của setTimeout chạy, vòng lặp đã kết thúc và biến i đã có giá trị là 3. Cả 3 callback đều trỏ tới cùng 1 ô nhớ.

Với let (Theo đặc tả ES6 §13.7.4.8) : Trong mỗi vòng lặp (iteration), JavaScript Engine tự động tạo ra một Lexical Environment (Block Scope) hoàn toàn mới ! Biến j của mỗi vòng lặp được copy giá trị từ vòng lặp trước và nằm ở một ô nhớ độc lập. Do đó, hàm closure của mỗi setTimeout giữ tham chiếu đến biến j riêng biệt của chính vòng lặp đó.

5. Góc phỏng vấn Senior Frontend

🎓 Q1: Tại sao nói "let và const không bị hoisting" là một nhận định sai lầm ?

Trả lời Top-Down chuẩn Senior :

"Nhận định đó sai vì nhầm lẫn giữa Hoisting và Initialization. Cả `let` và `const` đều được JavaScript Engine quét và đưa vào Declarative Environment Record ngay trong Creation Phase (tức là đã được Hoist). Bằng chứng rõ nhất là hiện tượng Shadowing: nếu trong một block scope ta khai báo `let x`, thì mọi lệnh truy cập `x` trước dòng đó sẽ lập tức ném ReferenceError chứ không thể kế thừa giá trị `x` từ scope cha. Điều này chứng minh Engine đã biết trước sự tồn tại của `x` cục bộ ngay từ đầu block."

🎓 Q2: Từ khóa const có giúp một Object trở nên bất biến (Immutable) hoàn toàn không ?

Trả lời Top-Down chuẩn Senior :

"Không. `const` trong JavaScript chỉ bảo vệ ràng buộc định danh (Variable Binding) trên Call Stack, tức là ngăn chặn việc gán lại biến sang ô nhớ khác (re-assignment). Nó không bảo vệ cấu trúc bên trong của đối tượng trên Memory Heap. Để biến một Object thành bất biến thật sự, lập trình viên phải sử dụng Object.freeze() (chỉ đóng băng 1 cấp nông) hoặc tự viết hàm deepFreeze đệ quy."
