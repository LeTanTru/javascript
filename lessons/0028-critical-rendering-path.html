1. Toàn cảnh 6 giai đoạn của Critical Rendering Path

BướcTên giai đoạnNhiệm vụ chínhĐặc tính
1 DOM Construction Bytes → Characters → Tokens → Nodes → DOM Tree Xử lý theo luồng (Streaming), tăng dần theo từng gói tin mạng
2 CSSOM Construction Bytes → Tokens → Rules → CSSOM Tree (Cascade styles) Render-Blocking: Trình duyệt không render đến khi CSSOM xong
3 Render Tree Kết hợp DOM + CSSOM, chỉ giữ lại các phần tử hiển thị Loại bỏ <head>, <script> và display: none
4 Layout (Reflow) Tính toán tọa độ hình học chính xác (x, y, width, height) của từng node Tốn kém CPU nhất khi có DOM mutation làm đổi kích thước
5 Paint (Repaint) Vẽ màu sắc, hình ảnh, văn bản, đường viền, bóng đổ lên các lớp (layers) Chuyển đổi các lệnh vẽ hình học thành bitmap điểm ảnh
6 Compositing Gửi các lớp (Layers) lên GPU để ghép lại và hiển thị lên màn hình Siêu nhanh, chạy trên GPU luồng riêng (Compositor Thread)

2. Bí mật của Render Tree: display: none vs visibility: hidden

💡 Câu hỏi phỏng vấn kinh điển

display: none và visibility: hidden khác nhau như thế nào ở tầng Render Engine ?

  • display: none → Phần tử hoàn toàn bị loại khỏi Render Tree. Trình duyệt không tạo Render Object, không tính toán Layout và không chiếm bất kỳ diện tích nào trên màn hình.
  • visibility: hidden / opacity: 0 → Phần tử VẪN NẰM TRONG RENDER TREE. Trình duyệt vẫn phải tính toán kích thước, vị trí trong giai đoạn Layout (chiếm khoảng trống), chỉ bỏ qua bước vẽ điểm ảnh ở Paint.

3. Cơ chế Script Blocking: Normal vs defer vs async

Cú phápTải file JS (Download)Thực thi file JS (Execute)Bảo toàn thứ tự ?
<script src="..."> Chặn HTML Parser ngay lập tức Chạy ngay khi tải xong (chặn tiếp HTML Parser) Có (theo thứ tự file)
<script defer src="..."> Tải ngầm song song (không chặn HTML Parser) Chạy sau khi HTML parse xong (ngay trước sự kiện DOMContentLoaded) Có (chuẩn cho code có phụ thuộc thư viện)
<script async src="..."> Tải ngầm song song (không chặn HTML Parser) Chạy ngay lập tức khi tải xong (tạm dừng HTML Parser lúc thực thi) Không (file nào tải xong trước chạy trước — dùng cho Google Analytics)

4. Ba tầng chi phí khi thay đổi CSS (Performance Triggers)

Không phải mọi thay đổi CSS đều có chi phí như nhau:

  • Layout Trigger (Tốn kém nhất) : width, height, margin, padding, top, left, font-size → Kích hoạt lại toàn bộ Layout → Paint → Composite.
  • Paint Trigger (Trung bình) : color, background-color, box-shadow, visibility → Kích hoạt lại Paint → Composite (bỏ qua Layout).
  • Composite Only (Tối ưu nhất - 60fps) : transform, opacity → Chỉ chạy trên GPU ở bước Composite (bỏ qua cả Layout và Paint)!
