1. Promise State Machine: 3 Trạng thái và Nguyên tắc 1 chiều

Mỗi Promise trong JavaScript là một cỗ máy trạng thái (State Machine) với đúng 3 trạng thái :

Trạng thái Ý nghĩa Giá trị nội bộ Có thể chuyển sang
pending Đang chờ — chưa có kết quả undefined fulfilled hoặc rejected
fulfilled Đã hoàn thành với giá trị thành công Giá trị bất kỳ (value) Không thể chuyển ! (Settled)
rejected Đã thất bại với lý do từ chối Error hoặc giá trị bất kỳ (reason) Không thể chuyển ! (Settled)
⚠ Quy tắc cốt lõi: Tính bất biến của trạng thái Promise

Một khi Promise đã rời khỏi trạng thái pending (chuyển sang fulfilled hoặc rejected), nó trở thành Settled và không bao giờ có thể thay đổi trạng thái lần nữa ! Gọi resolve() sau khi đã reject(), hoặc ngược lại, sẽ bị Engine hoàn toàn bỏ qua.

2. Promise Chaining: Tại sao .then() luôn trả về Promise mới ?

Đây là câu hỏi phỏng vấn quan trọng nhất về Promise. Câu trả lời nằm ở thuật toán Promise Resolution Procedure trong chuẩn ECMAScript :

  • Mỗi lần bạn gọi .then(onFulfilled), JavaScript Engine tạo ra một Promise mới hoàn toàn và đăng ký handler onFulfilled vào hàng đợi callbacks của Promise ban đầu.
  • Khi Promise ban đầu settle, handler được kích hoạt qua Microtask Queue. Giá trị trả về của handler (dù là primitive, object, hay một Promise khác) sẽ được dùng để resolve Promise mới này.
  • Nếu handler ném lỗi (throw), Promise mới sẽ tự động bị reject với lỗi đó.
JavaScript — Promise Chaining: Biến đổi giá trị đa tầng 
Promise.resolve(1)
  .then((v) => v + 1)    // → 2
  .then((v) => v * 3)    // → 6
  .then((v) => `Kết quả: ${v}`)  // → "Kết quả: 6"
  .then(console.log);   // In ra: "Kết quả: 6"

3. Error Propagation: Cơ chế "lan truyền lỗi nhảy cóc"

Đây là hành vi mà nhiều lập trình viên hiểu sai nhất. Khi một lỗi xảy ra trong một .then(), nó không bị "hấp thụ" ngay tại chỗ. Thay vào đó :

  1. Promise trả về bởi .then() đó chuyển sang trạng thái rejected.
  2. Lỗi lan truyền (propagate) qua tất cả các .then() tiếp theo, bỏ qua chúng hoàn toàn, cho đến khi gặp .catch() hoặc .then(_, onRejected) đầu tiên.
  3. Sau khi .catch() xử lý lỗi và trả về một giá trị bình thường, chuỗi trở lại trạng thái fulfilled và các .then() tiếp theo tiếp tục chạy bình thường.
JavaScript — Error Propagation qua chuỗi Promise 
Promise.resolve("ok")
  .then((v) => {
    throw new Error("Lỗi xảy ra !");
  })
  .then(() => {
    // ← BỊ BỎ QUA HOÀN TOÀN vì Promise phía trên đang rejected
    console.log("Không bao giờ chạy !");
  })
  .catch((err) => {
    console.log("Bắt lỗi:", err.message); // ← Lỗi dừng tại đây !
    return "Đã phục hồi";
  })
  .then((v) => {
    // ← CHẠY BÌNH THƯỜNG vì .catch() đã xử lý lỗi
    console.log(v); // "Đã phục hồi"
  });

4. Giải phẫu .finally(): Quy tắc "chạy nhưng không can thiệp"

.finally(onFinally) hành xử theo 2 nguyên tắc cứng :

  • Luôn chạy : Bất kể Promise trước đó là fulfilled hay rejected, callback onFinally đều được thực thi.
  • Trong suốt (Transparent) : .finally() KHÔNG thể biến đổi giá trị đang truyền qua chuỗi (trừ khi nó ném ra lỗi). Giá trị fulfilled hoặc lý do rejected được truyền thẳng xuống bước tiếp theo nguyên vẹn.
JavaScript — finally() trong suốt như tấm kính 
Promise.resolve(42)
  .finally(() => {
    // Thử trả về giá trị khác → bị bỏ qua hoàn toàn !
    return "Giá trị bị bỏ qua";
  })
  .then((v) => console.log(v)); // In ra: 42 (nguyên vẹn)
