1. Kiến trúc Pipeline của V8 Engine hiện đại

Để vừa có tốc độ khởi động trang web tức thì (Fast Startup) vừa đạt tốc độ thực thi tối đa (Peak Performance), V8 sử dụng kiến trúc Multi-Tier Compilation Pipeline (Biên dịch đa tầng) :

TầngTên thành phầnVai tròĐặc tính
0 Scanner / Parser Chuyển chuỗi mã nguồn JS thành AST (Abstract Syntax Tree) Bắt lỗi cú pháp (SyntaxError)
1 Ignition Bytecode Interpreter — chuyển AST thành Bytecode Khởi động cực nhanh, thu thập Type Feedback trong lúc chạy
2 Sparkplug Baseline Compiler — dịch Bytecode sang Machine Code không tối ưu Tăng tốc 2-3x mà không cần phân tích phức tạp
3 Maglev Mid-tier JIT Compiler (ES2023+) Cầu nối trung gian giữa Sparkplug và TurboFan
4 TurboFan Optimizing JIT Compiler — tạo Machine Code đỉnh cao Dựa trên giả định kiểu dữ liệu (Speculative Assumptions)

2. Speculative Optimization & Cơn ác mộng Deoptimization (Bailout)

JavaScript là ngôn ngữ Dynamic Typing (kiểu động), nhưng máy tính phần cứng chỉ hiểu các thanh ghi và phép toán số nguyên/số thực cố định.
Khi một hàm được gọi lặp đi lặp lại nhiều lần với cùng 1 kiểu dữ liệu (gọi là Hot Function), TurboFan sẽ đoán (Speculate) rằng các lần gọi sau cũng sẽ cùng kiểu đó để sinh mã máy Assembly chuyên biệt tốc độ cao.

⚠ Khi giả định bị phá vỡ: Deoptimization !

Nếu bạn huấn luyện hàm add(a, b) với 10,000 số nguyên add(1, 2), TurboFan tạo ra 1 lệnh CPU ADD duy nhất. Nhưng nếu lần thứ 10,001 bạn truyền add("hello", "world"), giả định bị sụp đổ!
V8 buộc phải Deoptimize (Bailout): vứt bỏ mã máy TurboFan và hạ cấp thực thi quay về Ignition Bytecode chậm hơn — gây sụt giảm hiệu năng đột ngột.

JavaScript — Minh họa JIT-Friendly vs Deopt Trigger 
// ✅ JIT-Friendly (Monomorphic): Kiểu tham số nhất quán 100%
function sumArray(arr) {
  let total = 0;
  for (let i = 0; i < arr.length; i++) {
    total += arr[i]; // Luôn là số nguyên (Smi - Small Integer) → TurboFan tối ưu tối đa
  }
  return total;
}

// ❌ Deopt Trigger (Polymorphic / Megamorphic): Trộn lẫn các kiểu dữ liệu
const mixed = [1, 2, "3", 4, { val: 5 }, null];
sumArray(mixed); // Gây Deoptimization liên tục trong vòng lặp!

3. Bí kíp viết Code thân thiện với JIT (JIT-Friendly Code)

  1. Giữ hàm ở trạng thái Monomorphic : Truyền đối số có cùng kiểu dữ liệu vào các hàm quan trọng (Hot functions).
  2. Khởi tạo Object với thứ tự thuộc tính nhất quán : Giúp V8 chia sẻ cùng một Hidden Class (Shape).
  3. Tránh dùng delete obj.prop : Lệnh delete làm biến dạng Hidden Class và biến object thành Dictionary Mode (chậm hơn 10x-50x). Thay vào đó, hãy gán obj.prop = undefined hoặc null.
  4. Tránh thay đổi mảng thưa thớt (Holey Arrays) : Mảng [1, 2, , 4] chứa "holes" khiến V8 phải duyệt chuỗi Prototype để tìm giá trị, vô hiệu hóa các tối ưu hóa mảng C++.
