1. Execution Context là gì ? Ba loại Context trong Runtime

Một Execution Context (EC) là một môi trường trừu tượng do JavaScript Engine tạo ra để theo dõi, quản lý việc đánh giá và thực thi mã nguồn. Bất cứ đoạn mã JavaScript nào khi chạy cũng đều nằm bên trong một Execution Context cụ thể.

Trong JavaScript Runtime, có 3 loại Execution Context :

Cấu trúc 3 loại Execution Context 
// 1. Global Execution Context (GEC):
// - Được tạo DUY NHẤT một lần ngay khi chương trình khởi động.
// - Tạo ra Global Object (window trên Browser, global trên Node.js) và binding 'this'.

// 2. Function Execution Context (FEC):
// - Được tạo MỖI KHI một hàm được GỌI (invoked), KHÔNG phải lúc khai báo.
// - Mỗi lời gọi hàm sinh ra một FEC riêng biệt với không gian biến độc lập.

// 3. Eval Execution Context:
// - Được tạo khi thực thi chuỗi mã bên trong hàm eval() (ít dùng vì rủi ro bảo mật & hiệu năng).

2. Vòng đời của Execution Context: Hai giai đoạn sống

Mỗi khi một Execution Context được kích hoạt, nó trải qua đúng hai giai đoạn riêng biệt :

Giai đoạn Thời điểm Hành vi của Engine Trạng thái biến & hàm
1. Creation Phase (Khởi tạo / Biên dịch) Khi hàm vừa được gọi, trước khi chạy bất kỳ dòng code nào Quét toàn bộ phạm vi để tạo Variable Object (VO), Scope Chain và this • function foo(){} → lưu cả tên và con trỏ thân hàm.
• var x → lưu tên biến, gán sẵn undefined.
2. Execution Phase (Thực thi) Ngay sau khi Creation Phase hoàn tất Chạy từng dòng lệnh từ trên xuống dưới theo thứ tự xuất hiện Thực hiện các phép gán giá trị thật (x = 10), tính toán biểu thức, gọi hàm khác.

3. Giải phẫu Creation Phase & Khái niệm Variable Object (VO)

Trong chuẩn ES3/ES5, thành phần lưu trữ các biến và hàm của Execution Context được gọi là Variable Object (VO) (với Function Context, nó được gọi là Activation Object - AO và có thêm thuộc tính arguments). Trong các phiên bản ES6+, khái niệm này được chuẩn hóa thành Environment Record.

Thứ tự quét của Engine trong Creation Phase diễn ra nghiêm ngặt như sau :

Thứ tự ưu tiên trong Creation Phase 
// Bước 1: Khởi tạo đối tượng arguments (đối với Function Context)
// Bước 2: Quét tất cả FUNCTION DECLARATIONS (Khai báo hàm tường minh)
//         -> Đưa tên hàm vào VO và trỏ thẳng tới vùng nhớ chứa thân hàm trên Heap!
// Bước 3: Quét tất cả VARIABLE DECLARATIONS với từ khóa 'var'
//         -> Đưa tên biến vào VO và gán giá trị khởi tạo là undefined.
//         -> ĐẶC BIỆT: Nếu tên biến 'var' TRÙNG với tên function đã quét ở Bước 2,
//            Engine sẽ BỎ QUA khai báo var, giữ nguyên hàm!
💡 Tại sao Function Declaration gọi trước được nhưng Function Expression thì không ?

Hãy phân tích đoạn mã kinh điển sau :

JavaScript 
sayHi();   // → Chạy bình thường: "Hi!"
sayBye();  // → TypeError: sayBye is not a function !

function sayHi() { console.log("Hi!"); }
var sayBye = function() { console.log("Bye!"); };

Bản chất dưới Creation Phase :

  • sayHi là Function Declaration → trong Creation Phase, VO.sayHi đã trỏ trực tiếp tới hàm thực thi trên Heap → gọi lúc nào cũng được.
  • sayBye được khai báo bằng var → trong Creation Phase, VO.sayBye = undefined. Khi sang Execution Phase, dòng gọi hàm sayBye() tương đương với undefined() → JavaScript Engine quăng TypeError (vì undefined không thể gọi như hàm) chứ không phải ReferenceError !

4. Call Stack & Quản lý vòng đời (Push / Pop)

JavaScript là ngôn ngữ đơn luồng (Single-threaded), có nghĩa là tại một thời điểm chỉ có duy nhất một Execution Context được thực thi. V8 Engine sử dụng Call Stack (Ngăn xếp lời gọi hàm) để điều phối luồng thực thi này :

  1. Khi chương trình bắt đầu → Global Execution Context (GEC) được khởi tạo và đẩy (Push) vào đáy của Call Stack.
  2. Mỗi khi gặp một lời gọi hàm → một Function Execution Context (FEC) mới được tạo và Push lên đỉnh Call Stack. Execution Context trên cùng luôn là context đang hoạt động (Active Context).
  3. Khi hàm chạy xong (gặp câu lệnh return hoặc kết thúc block) → FEC tương ứng được rút (Pop) khỏi đỉnh Call Stack, giải phóng các biến cục bộ (trừ khi có Closure), trao quyền thực thi lại cho context nằm ngay phía dưới.
⚠ Hiện tượng Stack Overflow (Tràn ngăn xếp)

Call Stack có giới hạn kích thước vùng nhớ vật lý (thường khoảng 10.000 đến 16.000 frames trên Chrome V8). Nếu một hàm đệ quy không có điểm dừng (infinite recursion), các FEC liên tục bị Push vào mà không bao giờ được Pop ra, dẫn tới lỗi kinh điển :

Console Error 
RangeError: Maximum call stack size exceeded

5. Góc phỏng vấn Senior Frontend

🎓 Q1: Hãy giải thích chính xác những gì xảy ra trong Creation Phase của một hàm ?

Trả lời Top-Down chuẩn Senior :

"Trong Creation Phase, Engine thực hiện 3 nhiệm vụ chính trước khi chạy code: (1) Khởi tạo Variable Environment (Environment Record), phân tích đối tượng arguments và các tham số truyền vào; (2) Quét và đăng ký toàn bộ khai báo hàm (Function Declarations) vào môi trường với tham chiếu đầy đủ; (3) Quét các khai báo biến `var` và cấp phát tên biến với giá trị khởi tạo `undefined`. Đồng thời, Engine thiết lập Scope Chain (liên kết với outer environment) và xác định binding cho từ khóa `this`."

🎓 Q2: Đoạn mã sau in ra gì trong console và tại sao ?
Câu hỏi phỏng vấn trắc nghiệm 
console.log(typeof foo);
var foo = "Antigravity";
function foo() {}
console.log(foo);

Trả lời Top-Down chuẩn Senior :

"Kết quả lần lượt là 'function' và 'Antigravity'. Lý do: Trong Creation Phase, Function Declaration foo được ưu tiên đăng ký trước vào Variable Object. Khi Engine duyệt đến var foo, vì định danh foo đã tồn tại nên khai báo var bị bỏ qua. Do đó tại dòng đầu tiên, foo là một hàm. Khi bước sang Execution Phase, lệnh gán foo = 'Antigravity' được thực thi, ghi đè biến foo thành string, nên dòng log thứ hai in ra 'Antigravity'."
