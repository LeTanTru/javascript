1. Phân biệt bản chất: Debounce vs Throttle

Khi người dùng gõ bàn phím liên tục, kéo resize cửa sổ hoặc cuộn trang (scroll), trình duyệt có thể phát ra hàng trăm sự kiện mỗi giây. Nếu mỗi sự kiện đều gọi API hoặc tính toán DOM, ứng dụng sẽ bị đơ (jank) hoặc gây quá tải server.

Tiêu chíDebounce (Hoãn thực thi)Throttle (Điều tiết nhịp độ)
Định nghĩa Gom nhiều lời gọi liên tiếp thành 1 lời gọi duy nhất sau khi người dùng ngừng thao tác một khoảng wait ms. Đảm bảo hàm được thực thi tối đa 1 lần trong mỗi khoảng thời gian wait ms cố định.
Reset Timer ? Có — Mỗi lần gọi mới trong khoảng wait sẽ hủy timer cũ và đếm lại từ đầu. Không — Chu kỳ thời gian chạy độc lập, không bị reset bởi các thao tác gọi mới.
Use Case kinh điển Auto-save form, Typeahead search / Autocomplete, Window Resize event. Infinite Scroll, Scroll spy (cập nhật active menu), Drag and Drop tracking, Throttle button clicks chống spam.

2. Live-coding: Cài đặt debounce() hoàn chỉnh

Cấu trúc của debounce gồm bộ đếm thời gian timerId, lưu giữ lastArgs và lastThis trong Closure scope để chuyển giao khi kích hoạt :

JavaScript — debounce polyfill (Hỗ trợ leading, trailing, .cancel(), .flush()) 
function debounce(fn, wait, options = {}) {
  const { leading = false, trailing = true } = options;
  let timerId = null;
  let lastArgs = null;
  let lastThis = null;
  let result;

  function invokeFn() {
    if (lastArgs !== null) {
      result = fn.apply(lastThis, lastArgs);
      lastArgs = null;
      lastThis = null;
    }
    return result;
  }

  function debounced(...args) {
    lastArgs = args;
    lastThis = this;

    const isInvokingLeading = leading && timerId === null;

    if (timerId !== null) {
      clearTimeout(timerId); // Reset timer nếu có call mới
    }

    timerId = setTimeout(() => {
      timerId = null;
      if (trailing && !isInvokingLeading) {
        invokeFn();
      }
    }, wait);

    if (isInvokingLeading) {
      invokeFn(); // Chạy ngay lập tức ở cạnh đầu (leading edge)
    }

    return result;
  }

  // Hủy bỏ timer đang chờ (tránh memory leak khi unmount component)
  debounced.cancel = function() {
    if (timerId !== null) {
      clearTimeout(timerId);
      timerId = null;
    }
    lastArgs = null;
    lastThis = null;
  };

  // Ép thực thi ngay lập tức không cần chờ timer
  debounced.flush = function() {
    if (timerId !== null) {
      clearTimeout(timerId);
      timerId = null;
      return invokeFn();
    }
    return result;
  };

  return debounced;
}

3. Live-coding: Cài đặt throttle() chuẩn Timestamp + Timer

Phương pháp kết hợp Timestamp (cho Leading execution) và Timer (cho Trailing execution) đảm bảo vừa phản hồi tức thì vừa không bỏ sót lần tương tác cuối cùng của người dùng :

JavaScript — throttle polyfill (Leading + Trailing) 
function throttle(fn, wait, options = {}) {
  const { leading = true, trailing = true } = options;
  let timerId = null;
  let lastArgs = null;
  let lastThis = null;
  let lastCallTime = 0;
  let result;

  function invokeFn(time) {
    lastCallTime = time;
    if (lastArgs !== null) {
      result = fn.apply(lastThis, lastArgs);
      lastArgs = null;
      lastThis = null;
    }
    return result;
  }

  function throttled(...args) {
    const now = Date.now();
    lastArgs = args;
    lastThis = this;

    if (lastCallTime === 0 && !leading) {
      lastCallTime = now;
    }

    const remaining = wait - (now - lastCallTime);

    // Đã hết chu kỳ wait -> Chạy ngay lập tức
    if (remaining <= 0 || remaining > wait) {
      if (timerId !== null) {
        clearTimeout(timerId);
        timerId = null;
      }
      invokeFn(now);
    } else if (timerId === null && trailing) {
      // Chưa hết chu kỳ -> Lên lịch cho lần gọi trailing cuối cùng
      timerId = setTimeout(() => {
        timerId = null;
        lastCallTime = leading ? Date.now() : 0;
        invokeFn(Date.now());
      }, remaining);
    }

    return result;
  }

  throttled.cancel = function() {
    if (timerId !== null) {
      clearTimeout(timerId);
      timerId = null;
    }
    lastCallTime = 0;
    lastArgs = null;
    lastThis = null;
  };

  return throttled;
}

4. Bẫy Memory Leak & Sử dụng chuẩn trong React

⚠ Cạm bẫy khi dùng Debounce trong React Component

Nếu bạn khai báo const debouncedFn = debounce(fn, 300) trực tiếp trong thân function component, mỗi lần component re-render sẽ tạo ra một hàm debounce mới toanh và timer cũ bị mồ côi (không reset được). Luôn sử dụng useCallback hoặc useMemo kèm hàm cleanup .cancel() trong useEffect !

React — Custom Hook useDebounce chuẩn mực 
function useDebouncedCallback(callback, wait) {
  const callbackRef = useRef(callback);
  callbackRef.current = callback;

  const debounced = useMemo(
    () => debounce((...args) => callbackRef.current(...args), wait),
    [wait]
  );

  useEffect(() => {
    return () => debounced.cancel(); // Cleanup khi unmount
  }, [debounced]);

  return debounced;
}
