1. Giả thuyết thế hệ & Phân vùng V8 Memory Heap

Bộ thu gom rác của V8 được thiết kế dựa trên The Generational Hypothesis (Giả thuyết thế hệ): "Hầu hết các đối tượng trong chương trình đều chết rất trẻ (vừa tạo ra đã hết giá trị sử dụng ngay sau khi hàm kết thúc)."

Phân vùng HeapKích thướcLoại Garbage CollectorGiải thuật dọn dẹp
New Space (Young Generation) Nhỏ (1MB – 64MB) Minor GC (Scavenger) Cheney's Copying Algorithm: Chia thành 2 semi-spaces (From-Space & To-Space). Sao chép object sống sang To-Space, giải phóng toàn bộ From-Space. Cực nhanh (1ms).
Old Space (Old Generation) Lớn (hàng trăm MB – vài GB) Major GC (Full Mark-Compact) Mark-Sweep-Compact (Orinoco project):
1. Marking: Đánh dấu từ GC Roots (Window, Stack, DOM).
2. Sweeping: Thu hồi các ô nhớ không được đánh dấu.
3. Compacting: Dồn các object còn sống lại sát nhau để chống phân mảnh bộ nhớ.

2. Bốn loại Memory Leaks phổ biến nhất trong JavaScript

  • 1. Biến Global vô tình tạo ra : Quên từ khóa const/let khiến biến bị gắn vào window (GC Roots) và không bao giờ bị thu hồi.
  • 2. Quên hủy Timers / Event Listeners : setInterval hoặc addEventListener giữ tham chiếu đến component sau khi đã unmount.
  • 3. Detached DOM Nodes : Giữ tham chiếu một thẻ HTML trong biến JavaScript sau khi đã xóa nó khỏi cây DOM (document.body.removeChild).
  • 4. Closures giữ thừa Scope : Hàm con vô tình lưu giữ một mảng dữ liệu khổng lồ của hàm cha ngoài ý muốn.

3. Tham chiếu yếu: WeakMap, WeakRef & FinalizationRegistry

Tham chiếu thông thường (Strong Reference) ngăn cản GC thu hồi đối tượng. Weak Reference (Tham chiếu yếu) cho phép bạn trỏ tới một object mà không ngăn cản GC thu gom nó khi mọi strong reference khác đã bị hủy :

JavaScript — Ứng dụng WeakRef & FinalizationRegistry (ES2021+) 
// 1. FinalizationRegistry: Đăng ký callback khi object bị thu hồi
const registry = new FinalizationRegistry((heldValue) => {
  console.log(`[Dọn dẹp]: Object với ID "${heldValue}" đã bị GC dọn dẹp hoàn toàn!`);
});

let user = { id: 101, name: 'Tru' };
registry.register(user, user.id);

// 2. WeakRef: Tạo tham chiếu yếu đến user
const userWeakRef = new WeakRef(user);

// Kiểm tra còn sống hay không qua deref()
console.log(userWeakRef.deref()?.name); // "Tru"

// Xóa Strong reference duy nhất
user = null;
// Khi GC chạy, user bị xóa khỏi RAM, userWeakRef.deref() trả về undefined
// và callback của registry tự động kích hoạt!
