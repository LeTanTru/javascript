Ở Bài 13, chúng ta đã nắm chắc 4 quy tắc vàng xác định this cho các hàm thông thường (Default, Implicit, Explicit, New Binding). Tuy nhiên, một trong những nỗi đau lớn nhất của JavaScript thời kỳ trước là hiện tượng Implicit Binding Loss trong các hàm callback bất đồng bộ (như setTimeout hay UI event handlers).

Để khắc phục triệt để vấn đề này, ES6 giới thiệu Arrow Functions (Hàm mũi tên). Nhưng Arrow Function không chỉ là cú pháp viết ngắn gọn; bên dưới tầng V8, nó vận hành theo một triết lý hoàn toàn khác biệt: Lexical `this`.

1. Bản chất Lexical this: Khi `this` trở thành một biến Scope

Quy tắc quan trọng nhất cần ghi nhớ :

"Arrow Function hoàn toàn KHÔNG CÓ ràng buộc `this` riêng (No `this` binding). Khi gặp từ khóa `this` bên trong Arrow Function, JavaScript Engine coi `this` giống hệt như một biến thông thường và tra cứu nó dọc theo Scope Chain từ môi trường từ vựng (Lexical Environment) bao bọc bên ngoài."

JavaScript — Thí nghiệm Lexical this trong Callback 
function Counter() {
  this.count = 0;

  // Dùng Regular Function → Mất context, this trỏ ra window/undefined !
  setTimeout(function () {
    // console.log(this.count++); // → NaN hoặc TypeError !
  }, 100);

  // Dùng Arrow Function → Kế thừa trực tiếp 'this' của Counter() !
  setTimeout(() => {
    this.count++;
    console.log("Count hiện tại:", this.count); // → In ra chính xác !
  }, 100);
}

new Counter();
⚠ Tại sao call(), apply(), bind() vô tác dụng với Arrow Function ?

Vì Arrow Function không hề có internal slot lưu trữ ngữ cảnh this, nên khi bạn cố tình gọi arrowFn.call(context) hoặc arrowFn.bind(context), Engine sẽ hoàn toàn bỏ qua tham số đầu tiên ! Bạn không thể ép buộc Arrow Function đổi context bằng bất kỳ API nào.

2. Bộ ba "bị tước bỏ": Tại sao không có arguments, prototype, new ?

Thành phần bị thiếu Hiện tượng khi cố tình truy cập / sử dụng Lý do kỹ thuật bên dưới Engine Giải pháp chuẩn hiện đại
arguments Sẽ đọc đối tượng arguments của hàm cha bao quanh nó (nếu có). Arrow Function được thiết kế tinh gọn cho lập trình hàm, không phân bổ đối tượng arguments riêng. Dùng Rest Parameters (...args)
prototype Trả về undefined (arrow.prototype === undefined). Arrow Function không được dùng để làm khuôn mẫu đối tượng; Engine tiết kiệm vùng nhớ Heap bằng cách không cấp phát prototype. Dùng Regular Function hoặc class
Toán tử new Ném TypeError: arrow is not a constructor. Arrow Function không có internal method [[Construct]], chỉ có [[Call]]. Dùng Regular Constructor hoặc class

3. Ba cái bẫy "chết người" khi dùng Arrow Functions

Bẫy 1: Khai báo Method trong Object Literal

JavaScript — Sai lầm kinh điển trong Object Literal 
const calculator = {
  factor: 2,
  // BẪY: Cặp ngoặc nhọn `{}` của Object KHÔNG tạo Scope !
  // Lexical Scope bên ngoài của hàm này là Global/Window Scope !
  multiply: (x) => x * this.factor,

  // ĐÚNG ĐẮN: Dùng Method Shorthand của ES6
  multiplyCorrect(x) {
    return x * this.factor; // 'this' là calculator
  }
};

console.log(calculator.multiply(5));        // → NaN (this.factor là undefined) !
console.log(calculator.multiplyCorrect(5)); // → 10 (Chuẩn xác)

Bẫy 2: Khai báo Prototype Method

Nếu bạn gán User.prototype.greet = () => { console.log(this.name); }, this vĩnh viễn trỏ về nơi đoạn code đó được thực thi (Global) thay vì trỏ tới từng instance được tạo ra bởi new User().

4. Góc phỏng vấn Senior Frontend

🎓 Q1: Tại sao Arrow Function không thể gọi bằng toán tử new ? Giải thích dưới góc độ ECMAScript internals ?

Trả lời Top-Down chuẩn Senior :

"Trong đặc tả ECMAScript, một hàm chỉ có thể dùng với `new` khi nó sở hữu internal method `[[Construct]]`. Arrow Function chỉ được Engine trang bị internal method `[[Call]]` mà bị khuyết thiếu hoàn toàn `[[Construct]]`. Khi Engine phát hiện lệnh `new` kích hoạt trên một hàm thiếu `[[Construct]]`, nó lập tức ném ra ngoại lệ `TypeError: ... is not a constructor`. Ngoài ra, vì không thể khởi tạo đối tượng, Engine cũng lược bỏ luôn thuộc tính `prototype` để tiết kiệm bộ nhớ Heap."

🎓 Q2: Khi nào NÊN và KHÔNG NÊN dùng Arrow Function trong dự án ?

Trả lời Top-Down chuẩn Senior :

"- **NÊN DÙNG:** Trong các hàm callbacks (như `map`, `filter`, `setTimeout`, Promise chaining), các hàm tiện ích pure function, hoặc khi muốn bảo toàn `this` của component cha (như Class Fields trong React component).
- **KHÔNG NÊN DÙNG:** Khi khai báo phương thức của Object literal, phương thức trên `prototype`, hàm khởi tạo Constructor, và các Event Handlers mà logic cần truy cập trực tiếp vào DOM element thông qua `this`."
