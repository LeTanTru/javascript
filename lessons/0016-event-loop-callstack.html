Bài 16 · Kiến trúc Event Loop trên Trình duyệt & Node.js (Call Stack, Task Queue, Microtask Queue)

Giải phẫu mô hình Concurrency Model đơn luồng (Single-threaded) của JavaScript, cơ chế điều phối giữa V8 Call Stack, Web APIs / Libuv, Task Queue và Microtask Queue.

⏳ ~22 phút · 🎯 Mục tiêu: Nắm vững giải thuật 1 tick của Event Loop theo chuẩn HTML Living Standard, phân biệt rạch ròi quy trình vét cạn Microtasks và cách một Macrotask được kích hoạt, nhận diện hiện tượng Event Loop Starvation.

🌉 Cầu nối từ Module 04 sang Module 05

Ở Module 04, chúng ta đã hiểu tường tận cách các hàm được kích hoạt và ngữ cảnh this được gắn kết. Tuy nhiên, một sự thật kỹ thuật căn bản : JavaScript Engine (như Google V8) là một môi trường đơn luồng (Single-threaded) — nó chỉ sở hữu duy nhất một Call Stack tại một thời điểm.

Vậy làm thế nào mà trình duyệt hay máy chủ Node.js có thể tải hàng trăm request mạng, nghe click chuột, chạy animation 120 FPS mà giao diện không hề bị đóng băng (freeze) ? Bí mật nằm ở kiến trúc ngoại vi bao bọc quanh Engine : Event Loop (Vòng lặp sự kiện).

1. Bốn trụ cột của JavaScript Concurrency Model

Một quan niệm sai lầm rất phổ biến của lập trình viên là nghĩ setTimeout hay fetch là tính năng của ngôn ngữ JavaScript. Thực chất, chúng là các API do môi trường lưu trữ (Hosting Environment — Trình duyệt hoặc Node.js) cung cấp !

Trụ cột Bản chất & Cấu trúc dữ liệu Nhiệm vụ chính
1. Call Stack Ngăn xếp LIFO (Last In, First Out) thuộc JavaScript Engine (V8). Nơi thực thi trực tiếp các dòng mã đồng bộ (Synchronous code). Chỉ có 1 Call Stack duy nhất chạy trên main thread.
2. Web APIs / Libuv Môi trường C++ đa luồng chạy ngầm của Browser (Web APIs) hoặc Node.js (Libuv C++ Threadpool). Xử lý các tác vụ tốn thời gian: đếm ngược timer, gửi request HTTP/HTTPS, đọc ghi file, lắng nghe DOM events.
3. Task Queue (Macrotask) Hàng đợi FIFO (First In, First Out). Chứa các callback đã hoàn thành chờ được đưa lên Call Stack: setTimeout, setInterval, UI Rendering events.
4. Microtask Queue Hàng đợi FIFO ưu tiên cao đặc biệt (High-priority queue). Chứa các tác vụ bất đồng bộ vi mô: Promise.then/catch/finally, queueMicrotask(), MutationObserver.

2. Giải thuật 1 Tick của Event Loop (Chuẩn HTML Living Standard)

Event Loop hoạt động giống như một vòng lặp while (true) liên tục giám sát Call Stack và các hàng đợi. Trong một chu kỳ quay (1 Tick), Event Loop tuân thủ thứ tự nghiêm ngặt sau :

  1. Thực thi Call Stack : Chạy mã đồng bộ cho đến khi Call Stack hoàn toàn rỗng.
  2. Vét cạn Microtask Queue (Drain Microtasks) :

    Lấy từng microtask ra và thực thi trên Call Stack. Điểm mấu chốt : Event Loop sẽ KHÔNG DỪNG LẠI cho đến khi Microtask Queue trống rỗng hoàn toàn ! Nếu một microtask tiếp tục tạo ra microtask mới, microtask mới sẽ được chạy tiếp ngay trong lượt này.

  3. Giai đoạn Render (Rendering Pipeline — chỉ có trên Trình duyệt) :

    Trình duyệt kiểm tra xem đã đến thời điểm làm mới khung hình chưa (thường là mỗi 16.6ms cho màn hình 60Hz). Nếu có, nó kích hoạt requestAnimationFrame, tính toán lại CSS Style, Layout và Paint giao diện lên màn hình.

  4. Bốc duy nhất 1 Macrotask :

    Event Loop bốc đúng một task đứng đầu từ Task Queue (Macrotask) đưa lên Call Stack để thực thi.

  5. Lặp lại vòng tuần hoàn : Quay lại Bước 2 (tiếp tục vét sạch mọi Microtask mới sinh ra từ Macrotask vừa chạy).
JavaScript — Thí nghiệm chứng minh chu kỳ 1 Tick 
console.log("1. Đồng bộ Start");

setTimeout(() => {
  console.log("4. Macrotask (setTimeout)");
}, 0);

Promise.resolve().then(() => {
  console.log("3. Microtask (Promise)");
});

console.log("2. Đồng bộ End");

// THỨ TỰ IN RA MÀN HÌNH:
// 1. Đồng bộ Start
// 2. Đồng bộ End
// 3. Microtask (Promise)  <-- Vét cạn trước khi rời tick
// 4. Macrotask (setTimeout) <-- Chỉ được bốc sau khi Microtask queue đã rỗng
⚠ Hiện tượng Microtask Starvation (Đóng băng trình duyệt)

Vì quy tắc "phải vét cạn toàn bộ Microtask Queue trước khi sang bước tiếp theo", nếu bạn tạo ra một chuỗi đệ quy microtask vô tận (ví dụ: một Promise .then() liên tục trả về chính nó), Call Stack và Microtask Queue sẽ bị khóa chết.

Hậu quả : Trình duyệt bị UI Freeze (treo đơ) hoàn toàn, người dùng không thể click chuột hay cuộn trang, và các setTimeout trong Macrotask Queue sẽ bị bỏ đói vĩnh viễn (Starvation) !

3. So sánh Event Loop: Trình duyệt vs Node.js (Libuv)

Mặc dù đều chạy JavaScript V8, cơ chế Event Loop bên dưới có kiến trúc phân tầng khác biệt :

Đặc điểm Event Loop trên Trình duyệt Event Loop trên Node.js (Libuv)
Tiêu chuẩn quy định Đặc tả HTML Living Standard (W3C / WHATWG). Thư viện C++ Libuv đa nền tảng.
Các giai đoạn (Phases) Mô hình phẳng: Stack → Microtasks → Render → 1 Macrotask. 6 Phases tuần hoàn :
1. Timers (setTimeout, setInterval)
2. Pending Callbacks (I/O lỗi hệ thống)
3. Idle, Prepare (nội bộ)
4. Poll (nhận I/O mới, đọc file/socket)
5. Check (setImmediate)
6. Close callbacks (socket.on('close'))
Hàng đợi ưu tiên đặc biệt Chỉ có Microtask Queue chuẩn (Promise, MutationObserver, queueMicrotask). Bổ sung process.nextTick Queue được xả cạn trước cả Promise microtasks tại các bước chuyển tiếp phase.
Render Pipeline Có (gắn liền với màn hình, CSSOM, Layout). Không có (Node.js là môi trường headless server).
