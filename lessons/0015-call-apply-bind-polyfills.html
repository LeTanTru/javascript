1. Bản chất cốt lõi: Kỹ thuật Property Hijacking với Symbol

Làm thế nào để một hàm fn thực thi với this là một đối tượng context hoàn toàn xa lạ mà không cần dùng hàm C++ gốc của Engine ?

Câu trả lời nằm ở Quy tắc 2 (Implicit Binding) chúng ta đã học ở Bài 13 :

"Nếu một hàm được gọi dưới dạng thuộc tính của một đối tượng (obj.method()), thì this bên trong hàm sẽ tự động trỏ tới đối tượng đứng trước dấu chấm !"

Vì vậy, giải thuật tự nhiên gồm 3 bước :

  1. Gán tạm hàm cần gọi làm một thuộc tính của context: context.tempFn = this.
  2. Kích hoạt hàm thông qua đối tượng đó: context.tempFn(...args) → this tự động là context !
  3. Xóa bỏ thuộc tính tạm để tránh làm biến đổi object gốc: delete context.tempFn.
⚠ Cạm bẫy trùng lặp Key & Giải pháp Symbol

Nếu bạn đặt tên thuộc tính tạm là chuỗi thông thường như context.__fn__ = this, bạn có nguy cơ ghi đè lên dữ liệu đã có sẵn của người dùng nếu object của họ cũng có thuộc tính đó !

Giải pháp chuẩn mực của ECMAScript 6 : Sử dụng Symbol('fnKey') để tạo ra một định danh duy nhất tuyệt đối, không thể xung đột với bất kỳ key nào.

2. Live-coding Polyfill: Function.prototype.myCall & myApply

Hãy chú ý xử lý 2 trường hợp biên (Edge cases) quan trọng :

  • Null hoặc Undefined Context : Trong Non-strict mode, nếu truyền null hoặc undefined, this phải fallback về globalThis (window trên trình duyệt hoặc global trong Node.js).
  • Primitive Context : Nếu người dùng truyền số 42 hay chuỗi "hello", hàm phải bọc nó thành Object Wrapper thông qua Object(context) trước khi gán Symbol.
JavaScript — Cài đặt myCall & myApply 
// Polyfill myCall: nhận danh sách đối số rời rạc (...args)
Function.prototype.myCall = function (context, ...args) {
  // 1. Xử lý context: null/undefined -> globalThis; primitive -> Object()
  if (context === null || context === undefined) {
    context = globalThis;
  } else {
    context = Object(context);
  }

  // 2. Dùng Symbol làm key duy nhất để tránh ô nhiễm context
  const fnKey = Symbol('fnKey');
  context[fnKey] = this; // 'this' chính là hàm đang gọi myCall

  // 3. Kích hoạt hàm qua Implicit Binding và hứng kết quả
  const result = context[fnKey](...args);

  // 4. Dọn dẹp thuộc tính tạm
  delete context[fnKey];

  return result;
};

// Polyfill myApply: nhận đối số thứ hai dưới dạng một mảng (argsArray)
Function.prototype.myApply = function (context, argsArray) {
  if (context === null || context === undefined) {
    context = globalThis;
  } else {
    context = Object(context);
  }

  const fnKey = Symbol('fnKey');
  context[fnKey] = this;

  let result;
  // Kiểm tra nếu có mảng đối số thì phân rã, nếu không thì gọi không tham số
  if (!argsArray || !Array.isArray(argsArray)) {
    result = context[fnKey]();
  } else {
    result = context[fnKey](...argsArray);
  }

  delete context[fnKey];
  return result;
};

3. Live-coding Polyfill: Function.prototype.myBind (Đỉnh cao Interview)

Viết polyfill cho bind() phức tạp hơn gấp nhiều lần vì nó mang 3 đặc tính :

  1. Trả về một hàm mới (Closure) : Không kích hoạt hàm ngay mà đóng gói hàm và context vào một bao đóng.
  2. Partial Application (Currying) : Hỗ trợ gộp các đối số truyền trước lúc bind() với các đối số truyền sau khi hàm mới được gọi.
  3. Toán tử new ghi đè (The `new` Keyword Override) : Đây là tiêu chí phân biệt Junior với Senior ! Chuẩn ECMAScript quy định : Nếu hàm được trả về từ bind() được gọi cùng từ khóa new, thì this lúc này PHẢI là thực thể mới tạo ra, và đối tượng context đã truyền vào lúc bind phải bị bỏ qua hoàn toàn !
JavaScript — Cài đặt myBind hoàn chỉnh chuẩn ECMAScript 
Function.prototype.myBind = function (context, ...bindArgs) {
  const originalFn = this;
  if (typeof originalFn !== 'function') {
    throw new TypeError('myBind phải được gọi trên một Function');
  }

  function boundFn(...callArgs) {
    // KIỂM TRA ĐIỀU KIỆN NEW:
    // Nếu boundFn được gọi bằng `new boundFn()`, thì trong hàm này:
    // 'this' là một instance kế thừa từ boundFn -> (this instanceof boundFn === true)
    const isNewInstance = this instanceof boundFn;

    // Nếu gọi với new -> context là chính 'this' mới; ngược lại dùng context đã bind
    const targetContext = isNewInstance ? this : (context ?? globalThis);

    // Nối đối số currying: bindArgs + callArgs
    return originalFn.apply(targetContext, [...bindArgs, ...callArgs]);
  }

  // Giữ nguyên chuỗi Prototype để các instance tạo từ new boundFn() có đầy đủ method
  if (originalFn.prototype) {
    boundFn.prototype = Object.create(originalFn.prototype);
  }

  return boundFn;
};
💡 Tại sao cần Object.create(originalFn.prototype) ?

Nếu bạn gán trực tiếp boundFn.prototype = originalFn.prototype, bất kỳ sửa đổi nào trên boundFn.prototype sẽ làm biến dạng luôn cả originalFn.prototype ! Dùng Object.create() tạo ra một prototype trung gian độc lập nhưng vẫn duy trì chuỗi Prototype Chain hoàn hảo.

4. Bảng tổng kết so sánh 3 phương thức

Phương thức Thời điểm thực thi Cách truyền tham số Giá trị trả về Ảnh hưởng của `new`
call(context, ...args) Thực thi ngay lập tức Liệt kê đối số rời rạc Kết quả của hàm Không áp dụng
apply(context, [args]) Thực thi ngay lập tức Mảng đối số (hoặc array-like) Kết quả của hàm Không áp dụng
bind(context, ...args) Không thực thi ngay Truyền trước một phần (Currying) Hàm mới (Bound Function) Ghi đè context đã bind
