Tổng hợp kiến thức Module 02 : Execution Context, Scope Chain & Closures

Bản đồ tư duy tóm lược cô đọng toàn bộ kiến thức nền tảng từ Bài 05 đến Bài 08 — Sẵn sàng cho phỏng vấn Senior Frontend và tối ưu hóa bộ nhớ chuyên sâu.

⏳ ~20 phút · 🎯 Mục tiêu: Nắm vững 4 trục kiến thức cốt lõi (Execution Context, Hoisting/TDZ, Scope Chain/Lexical Scope, Closures & Memory Leaks).

1. Trục 1: Execution Context & Call Stack (Bài 05)

Giai đoạn Hành động của JavaScript Engine Trạng thái biến & hàm
Creation Phase (Khởi tạo) 1. Khởi tạo Scope Chain.
2. Cấp phát Variable Object / Environment Record.
3. Xác định giá trị liên kết this. 		- Function Declarations: Lưu toàn bộ định nghĩa hàm vào ô nhớ.
- var: Đăng ký tên biến và gán mặc định undefined.
- let / const: Đăng ký tên biến nhưng rơi vào TDZ (chưa cấp phát ô nhớ).
Execution Phase (Thực thi) Duyệt mã nguồn từ trên xuống dưới theo từng dòng lệnh, tính toán biểu thức và gọi hàm. Gán giá trị thực tế cho biến (Assignment) và thực thi logic nghiệp vụ.

2. Trục 2: Vòng đời biến, Hoisting & TDZ (Bài 06)

Từ khóa Thời điểm Declaration Thời điểm Initialization Hành vi khi gọi trước khai báo ? Phạm vi (Scope)
var Creation Phase Creation Phase (gán undefined) Trả về undefined Function Scope (Rò rỉ qua block {})
let Creation Phase Execution Phase (chạm dòng khai báo) ReferenceError (dính TDZ) Block Scope (Đóng gói trong {})
const Creation Phase Execution Phase (cùng lúc với Assignment) ReferenceError (dính TDZ) Block Scope (Không cho phép gán lại)

3. Trục 3: Lexical Environment & Scope Chain (Bài 07)

CẤU TRÚC DỮ LIỆU

Lexical Environment

Gồm 2 thành phần: Environment Record (bảng ghi biến/hàm) và con trỏ outer tham chiếu tới phạm vi cha.

Scope Chain bản chất là một Singly Linked List kết nối các Environment Records từ trong ra ngoài đến Global Environment (nơi có outer === null).

QUY TẮC BẤT BIẾN

Lexical Scoping (Static Scope)

Phạm vi của một hàm được quyết định cố định tại nơi hàm được ĐỊNH NGHĨA trong mã nguồn, hoàn toàn KHÔNG PHỤ THUỘC vào nơi hàm được GỌI (Call-site).

Khi hàm con gọi hàm, nó tra cứu biến dọc theo Scope Chain từ vị trí định nghĩa tĩnh của nó.

4. Trục 4: Closures & Săn tìm Memory Leaks (Bài 08)

Khái niệm / Kịch bản Bản chất kỹ thuật tầng Engine Giải pháp / Lưu ý Senior
Bản chất Closures V8 Scope Analysis phát hiện biến closed-over → Thực hiện Context Allocation chuyển biến từ Stack lên Memory Heap. Con trỏ [[Environment]] giữ Context Object không bị GC thu dọn. Nền tảng của Module Pattern, Currying, Memoization và Private State.
Dangling DOM Listener Element bị xóa khỏi DOM nhưng chưa gọi removeEventListener → Closure giữ tham chiếu khiến cả DOM Node và Context Object kẹt trên Heap (Detached DOM Tree). Luôn trả về hàm unsubscribe() hoặc sử dụng AbortController với { signal }.
Shared Lexical Scope Leak Nhiều hàm con trong cùng context chia sẻ chung 1 Context Object trên Heap. Một hàm nhỏ toàn cục có thể vô tình giữ lại mảng khổng lồ của một hàm con khác không còn dùng tới. Gán biến trung gian về null sau khi xử lý xong các payload dữ liệu lớn.
Shallow vs Retained Size Shallow Size: Kích thước của chính đối tượng.
Retained Size: Tổng lượng RAM sẽ được giải phóng ngay lập tức nếu đối tượng bị tiêu hủy.		 Khi soi Chrome DevTools Heap Snapshot, luôn sắp xếp theo Retained Size giảm dần để tìm thủ phạm gây leak.
