1. Giải mã async / await: Chạy đồng bộ hay bất đồng bộ ?

Rất nhiều lập trình viên hiểu lầm rằng hàm async sẽ đẩy toàn bộ nội dung của nó vào hàng đợi bất đồng bộ. Đây là một sai lầm chết người !

Quy tắc kỹ thuật của V8 Engine :

  • Phần mã đứng TRƯỚC từ khóa await : Thực thi hoàn toàn ĐỒNG BỘ trên Call Stack ngay tại thời điểm hàm được gọi !
  • Tại dòng chứa await expr : Biểu thức expr được thực thi ngay lập tức và được bọc thành Promise.resolve(expr).
  • Toàn bộ phần mã đứng SAU await : Bị tạm dừng (pause), được đóng gói tương đương với một callback trong .then() và được đẩy vào Microtask Queue !
JavaScript — Giải phẫu bản chất async/await 
async function demoAsync() {
  console.log("2. Trước await (ĐỒNG BỘ !)");
  await Promise.resolve();
  console.log("4. Sau await (Được đẩy vào Microtask Queue)");
}

console.log("1. Bắt đầu script");
demoAsync();
console.log("3. Kết thúc script");

// THỨ TỰ IN LOG:
// 1. Bắt đầu script
// 2. Trước await (ĐỒNG BỘ !)
// 3. Kết thúc script
// 4. Sau await (Microtask)

2. Vị trí của requestAnimationFrame & Rendering Pipeline

Màn hình máy tính thông thường làm mới ở tần số 60Hz (16.6ms / frame) hoặc 120Hz (8.3ms / frame). Trong khoảng thời gian 16.6ms đó, Event Loop có thể quay hàng chục hoặc hàng trăm tick microtask/macrotask, nhưng trình duyệt CHỈ VẼ LẠI GIAO DIỆN (Paint) khi đến nhịp V-Sync của phần cứng !

Quy trình Rendering Pipeline trong 1 Frame gồm các bước :

  1. Thực thi 1 Macrotask và vét sạch các Microtask phát sinh.
  2. Kích hoạt các callback của requestAnimationFrame (rAF) : Được gọi ngay trước khi trình duyệt tính toán lại Style/Layout để bạn có thể cập nhật các thuộc tính DOM cần vẽ.
  3. Recalculate Styles & Layout (Reflow) : Tính toán vị trí và hình học của các phần tử.
  4. Update Layer Tree & Paint : Vẽ các pixel lên màn hình thông qua GPU Compositor.
💡 Tại sao setTimeout(fn, 0) gây giật lag khi làm animation ?

Nếu bạn dùng setTimeout để làm animation, callback của timer có thể bị kích hoạt lệch pha với nhịp V-Sync của màn hình (ví dụ: kích hoạt 2 lần trong 1 frame hoặc bị hoãn sang frame sau), gây ra hiện tượng Frame Dropping (rớt khung hình) và giật lag.

requestAnimationFrame được thiết kế để khớp 100% với nhịp refresh của phần cứng, đảm bảo hiệu ứng đạt 60 FPS hoặc 120 FPS mượt mà tuyệt đối.

3. queueMicrotask: API Microtask chính thống của W3C

Trước ES2020, để chủ động đưa một hàm vào Microtask Queue mà không có sẵn Promise, lập trình viên thường phải "hack" bằng cách viết :

Promise.resolve().then(callback);

Nhược điểm của cách này :

  • Engine phải cấp phát một đối tượng Promise mới trên Memory Heap (tốn RAM và tăng tải cho Garbage Collector).
  • Nếu trong callback ném lỗi mà không có .catch(), nó sẽ phát sinh UnhandledPromiseRejection.

Chuẩn web hiện đại giới thiệu queueMicrotask(callback) :

queueMicrotask(() => {
  // Được đẩy trực tiếp vào Microtask Queue của V8 ở tầng C++ !
  // Không tạo Promise object, siêu nhẹ và tối ưu bộ nhớ Heap.
});

4. Ma trận & Thuật toán 4 bước "Bẻ khóa" câu đố Execution Order

Khi gặp bất kỳ bài tập thứ tự thực thi nào, hãy vẽ 2 hàng đợi ra nháp : [Microtask Queue] và [Macrotask Queue] và thực hiện đúng 4 bước :

Bước Hành động Quy tắc ghi nhớ
Bước 1 Chạy mã đồng bộ (Call Stack) từ trên xuống dưới. Gặp console.log → in ngay; gặp setTimeout → đẩy vào Task Queue; gặp Promise.then/queueMicrotask → đẩy vào Microtask Queue.
Bước 2 Vét cạn Microtask Queue theo thứ tự FIFO. Nếu trong lúc chạy microtask lại sinh ra microtask con → chạy tiếp ngay trong lượt này đến khi hàng đợi RỖNG TUẾCH.
Bước 3 Kiểm tra Render Pipeline (nếu có requestAnimationFrame). Chạy rAF trước khi vẽ màn hình.
Bước 4 Bốc ĐÚNG 1 Macrotask từ Task Queue đưa lên Call Stack. Sau khi Macrotask này chạy xong → lập tức quay lại Bước 2 để vét sạch Microtask mới sinh !
JavaScript — Bài toán phỏng vấn kinh điển: Tác vụ lồng nhau 
// Nhánh A: setTimeout chứa Promise
setTimeout(() => {
  console.log("Macro A (setTimeout ngoài)");
  Promise.resolve().then(() => {
    console.log("Micro A (Promise trong setTimeout)");
  });
}, 0);

// Nhánh B: Promise chứa setTimeout
Promise.resolve().then(() => {
  console.log("Micro B (Promise ngoài)");
  setTimeout(() => {
    console.log("Macro B (setTimeout trong Promise)");
  }, 0);
});

// THỨ TỰ THỰC THI CHUẨN XÁC:
// 1. "Micro B (Promise ngoài)"             <-- Microtask ngoài chạy trước Macrotask
// 2. "Macro A (setTimeout ngoài)"          <-- Bốc Macrotask đầu tiên (Macro A)
// 3. "Micro A (Promise trong setTimeout)"  <-- Vét cạn Microtask sinh ra bởi Macro A
// 4. "Macro B (setTimeout trong Promise)"  <-- Bốc Macrotask kế tiếp (Macro B)
