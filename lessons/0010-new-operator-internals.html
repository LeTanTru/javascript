1. Giải phẫu 4 bước của toán tử new (ECMA-262 §13.3.5.1)

Khi JavaScript Engine bắt gặp từ khóa new Constructor(...args), nó tự động kích hoạt internal method [[Construct]] và thực thi đúng 4 bước tuần tự sau :

  1. Tạo Object rỗng mới trên Memory Heap : Cấp phát một vùng nhớ đối tượng hoàn toàn mới: const instance = {}.
  2. Liên kết Prototype Chain : Gán instance.[[Prototype]] = Constructor.prototype (sử dụng Object.create hoặc Object.setPrototypeOf). Nhờ bước này, instance thừa hưởng mọi phương thức trên prototype của constructor.
  3. Gán ngữ cảnh this và thực thi hàm : Kích hoạt hàm Constructor với từ khóa this được trỏ thẳng vào instance vừa tạo: const result = Constructor.apply(instance, args). Các lệnh như this.name = name sẽ ghi trực tiếp thuộc tính vào instance.
  4. Kiểm tra giá trị trả về (The Return Trap) :
    • Nếu hàm Constructor trả về một Object hoặc Function (và không phải null) → Toán tử new sẽ trả về Object đó (ghi đè instance ban đầu !).
    • Nếu hàm trả về Primitive (Number, String, Boolean, Symbol, BigInt, Undefined, Null) → Giá trị return bị hoàn toàn bỏ qua, toán tử new trả về instance đã tạo ở bước 1.

2. Live-coding: Tự viết Polyfill myNew() chuẩn 100%

Đây là bài toán live-coding kiểm tra JavaScript Core xuất hiện thường xuyên nhất trong các vòng phỏng vấn kỹ thuật :

JavaScript — Cài đặt polyfill myNew 
function myNew(Constructor, ...args) {
  // Bước 1 & 2: Tạo object mới và liên kết [[Prototype]] tới Constructor.prototype
  const instance = Object.create(Constructor.prototype);

  // Bước 3: Thực thi hàm constructor với this là instance
  const result = Constructor.apply(instance, args);

  // Bước 4: Kiểm tra kết quả trả về
  const isObject = (typeof result === "object" && result !== null) || typeof result === "function";

  return isObject ? result : instance;
}
⚠ Bẫy kinh điển: Constructor return Primitive vs Object
JavaScript — Thí nghiệm Return Trap 
function Foo() {
  this.x = 10;
  return "Hello World"; // Return Primitive → BỊ LỜ ĐI !
}
const foo = new Foo();
console.log(foo.x); // → 10 (Vẫn nhận instance thông thường)

function Bar() {
  this.x = 10;
  return { override: true }; // Return Object → GHI ĐÈ INSTANCE !
}
const bar = new Bar();
console.log(bar.x);        // → undefined !
console.log(bar.override); // → true (bar chính là object được return)

3. new.target & Safe Constructor Pattern

Trong ES6, new.target là một meta-property được tạo ra để phát hiện xem một hàm hoặc constructor có đang được gọi thông qua từ khóa new hay không :

  • Khi gọi thông thường Fn(): new.target có giá trị là undefined.
  • Khi gọi với new Fn(): new.target trỏ trực tiếp tới chính hàm Fn.
JavaScript — Safe Constructor Pattern 
function User(name) {
  // Nếu lập trình viên quên gõ 'new', tự động kích hoạt 'new' thay họ
  if (!new.target) {
    return new User(name);
  }
  this.name = name;
}

const u1 = new User("Alice");
const u2 = User("Bob"); // Không có 'new' nhưng vẫn tạo instance an toàn !

console.log(u2 instanceof User); // → true
console.log(u2.name);            // → "Bob"

5. Góc phỏng vấn Senior Frontend

🎓 Q1: Nếu một constructor function trả về `null`, toán tử `new` sẽ trả về gì ? Tại sao ?

Trả lời Top-Down chuẩn Senior :

"Toán tử `new` sẽ trả về **instance vừa được tạo**, chứ không trả về `null`. Mặc dù trong JavaScript `typeof null === 'object'` (do bug lịch sử 3-bit type tag), nhưng đặc tả ECMAScript §13.3.5.1 quy định rõ: toán tử `new` chỉ trả về giá trị return khi giá trị đó là một Object thực sự theo Type(result) === Object. Trong mô hình của spec, Null là một Primitive Type độc lập, do đó nó bị bỏ qua giống hệt như số hay chuỗi."

🎓 Q2: Hãy tự viết lại hàm Object.create bằng cú pháp ES5 chỉ trong 4 dòng code ?

Trả lời Top-Down chuẩn Senior :

"Trước khi có `Object.create` trong ES5, các lập trình viên sử dụng kỹ thuật tạo một hàm tạm F rỗng: `function create(proto) { function F() {} F.prototype = proto; return new F(); }`. Kỹ thuật này tận dụng toán tử `new` để gán `proto` vào `[[Prototype]]` của instance mới mà không cần thực thi logic nghiệp vụ nào."
