1. Bài toán: Rate Limiting trong Async Workflows

Giả sử bạn cần xử lý 100 hình ảnh bằng API: nếu gọi Promise.all(images.map(upload)), bạn khởi tạo 100 request ngay lập tức. Hậu quả :

  • Server chịu 100 concurrent requests → quá tải, timeout, lỗi 503.
  • Browser mở 100 TCP connections cùng lúc → cạn kiệt bộ nhớ, crash tab.
  • Không thể kiểm soát thứ tự xử lý hay biết khi nào pool còn slot trống.

Yêu cầu lý tưởng : Luôn giữ tối đa N requests đang chạy song song. Khi 1 request hoàn thành, tự động kích hoạt request tiếp theo trong hàng đợi (Sliding Window).

2. Kiến trúc Concurrency Limiter: Queue + Closure + Callback Chain

Giải thuật cốt lõi gồm 3 thành phần :

  1. Queue (Hàng đợi FIFO) : Lưu trữ các task chưa được chạy, mỗi phần tử gồm taskFactory (hàm tạo Promise), resolve và reject của Promise bên ngoài.
  2. Active Counter : Biến activeCount đếm số tasks đang thực thi. Bất biến quan trọng : activeCount ≤ concurrency mọi lúc.
  3. next() Trigger : Hàm kích hoạt task kế tiếp, được gọi đệ quy trong .finally() của mỗi task hoàn thành (Sliding Window).
JavaScript — Concurrency Limiter hoàn chỉnh (chuẩn p-limit) 
function createConcurrencyLimiter(concurrency) {
  const queue = [];      // Hàng đợi tasks chờ xử lý
  let activeCount = 0;  // Reference Counter: số tasks đang chạy

  const next = () => {
    if (queue.length === 0 || activeCount >= concurrency) return;

    activeCount++;
    const { taskFactory, resolve, reject } = queue.shift();

    Promise.resolve(taskFactory())
      .then(resolve, reject)
      .finally(() => {
        activeCount--;  // Giải phóng slot
        next();       // ← Sliding Window: bốc task tiếp theo
      });
  };

  return function limit(taskFactory) {
    return new Promise((resolve, reject) => {
      queue.push({ taskFactory, resolve, reject }); // Xếp hàng
      next(); // Thử kích hoạt ngay (nếu còn slot)
    });
  };
}

3. Ứng dụng thực tế: Hàm asyncPool

Xây dựng helper function tương tự p-map để xử lý danh sách với concurrency control :

JavaScript — asyncPool: Batch API calls với concurrency control 
async function asyncPool(items, concurrency, mapper) {
  const limit = createConcurrencyLimiter(concurrency);
  return Promise.all(
    items.map((item) => limit(() => mapper(item)))
  );
}

// Sử dụng: Upload tối đa 3 file đồng thời
const files = [file1, file2, ..., file100];
const results = await asyncPool(files, 3, async (file) => {
  const url = await uploadToS3(file);
  return url;
});
// results là mảng 100 URLs theo đúng thứ tự ban đầu
💡 Bí mật của Sliding Window

Điểm then chốt là gọi next() trong .finally() (không phải .then()) để đảm bảo slot luôn được giải phóng và task mới được bốc bất kể task cũ thành công hay thất bại. Điều này ngăn chặn tình trạng pool bị "kẹt" do task lỗi.
