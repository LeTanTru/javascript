this hoàn toàn KHÔNG PHỤ THUỘC vào nơi hàm được khai báo, mà phụ thuộc 100% vào vị trí và cách thức hàm được GỌI (Call-site) ! Hiểu rõ 4 quy tắc binding là nền tảng để bạn làm chủ mọi thư viện, UI component và vượt qua mọi câu hỏi phỏng vấn hóc búa về output code.

1. Bảng thang bậc ưu tiên 4 quy tắc xác định this

Khi một hàm thông thường được kích hoạt, JavaScript Engine duyệt qua thang đo ưu tiên từ cao xuống thấp (từ 1 đến 4) để xác định giá trị của this :

Thứ bậc ưu tiên Quy tắc Binding Cú pháp kích hoạt tại Call-site Giá trị của `this`
1 (Cao nhất) New Binding new Fn() Trỏ tới instance đối tượng mới vừa được khởi tạo bởi Engine trên Heap.
2 Explicit Binding fn.call(ctx), fn.apply(ctx), fn.bind(ctx) Trỏ tới đối tượng context được lập trình viên chỉ định tường minh.
3 Implicit Binding obj.fn() Trỏ tới đối tượng chứa ngay trước dấu chấm (Calling Object / Context).
4 (Thấp nhất) Default Binding fn() (Hàm gọi trần độc lập) - Strict Mode: undefined.
- Non-strict Mode: window (browser) hoặc global (Node.js).

2. Phân tích chi tiết từng quy tắc & Strict Mode

2.1. Quy tắc 1: Default Binding & Vai trò cứu mạng của Strict Mode

Khi hàm được gọi độc lập không có dấu chấm và không có new hay call/apply, Engine áp dụng quy tắc mặc định :

JavaScript — Default Binding 
function showContext() {
  console.log(this);
}

// Trong Non-Strict Mode:
showContext(); // → window (Trình duyệt) hoặc global (Node.js)

// Trong Strict Mode ("use strict" hoặc ES Module):
function strictShow() {
  "use strict";
  console.log(this);
}
strictShow(); // → undefined !
💡 Tại sao Strict Mode lại gán this = undefined ?

Trong non-strict mode thời kỳ đầu của JavaScript, nếu bạn viết this.count = 0 bên trong một hàm gọi trần, bạn sẽ vô tình tạo ra một thuộc tính toàn cục window.count ! Đây là nguyên nhân gây ô nhiễm bộ nhớ và xung đột biến kinh hoàng. Strict Mode thiết lập this = undefined để nếu bạn lỡ truy cập this.count, Engine lập tức ném lỗi TypeError: Cannot set property of undefined, giúp lập trình viên bắt ngay bug từ sớm.

2.2. Quy tắc 2: Implicit Binding & Bẫy mất liên kết (Implicit Binding Loss)

Khi hàm được gọi thông qua một đối tượng (obj.method()), this trỏ về obj. Tuy nhiên, liên kết này rất lỏng lẻo và dễ bị "rơi rụng" :

JavaScript — Hiện tượng mất liên kết Implicit 
const person = {
  name: "Hoàng",
  getName() {
    return this.name;
  }
};

// Trường hợp 1: Gọi qua dấu chấm → Implicit Binding
console.log(person.getName()); // → "Hoàng"

// Trường hợp 2: Gán hàm sang một biến khác → MẤT LIÊN KẾT !
const fn = person.getName;
console.log(fn()); // → undefined (rơi về Default Binding !)

// Trường hợp 3: Truyền làm callback trong setTimeout / Event Listener
setTimeout(person.getName, 100); // → undefined (Callback được Web API gọi trần !)

3. So sánh cuộc chiến ưu tiên: New vs Hard Binding

Một câu hỏi phỏng vấn kinh điển: "Nếu một hàm vừa được bind() cứng vào context A, nhưng lại được gọi với từ khóa new, thì this sẽ trỏ về A hay trỏ về instance mới ?"

JavaScript — Cuộc chiến giữa new và bind 
function User(name) {
  this.name = name;
}

const forcedContext = { name: "Context Cố Định" };
const BoundUser = User.bind(forcedContext);

const instance = new BoundUser("Đối tượng mới");

console.log(instance.name);      // → "Đối tượng mới" !
console.log(forcedContext.name); // → "Context Cố Định" (Không hề bị thay đổi)

Kết luận : new Binding có độ ưu tiên cao hơn Hard Binding (bind) ! Toán tử new có quyền năng tối thượng ghi đè lên context đã bị khóa bởi bind() để đảm bảo instance mới luôn được tạo ra với danh tính riêng biệt.

4. Góc phỏng vấn Senior Frontend

🎓 Q1: Nêu 4 bước xác định `this` khi đọc một đoạn code bất kỳ ?

Trả lời Top-Down chuẩn Senior :

"Để xác định `this`, ta luôn nhìn vào **Call-site (vị trí gọi hàm)** và áp dụng thang 4 câu hỏi: 1. Hàm có được gọi với `new` không? → Nếu có, `this` là instance mới. 2. Hàm có được gọi với `call`, `apply` hoặc `bind` không? → Nếu có, `this` là context chỉ định. 3. Hàm có được gọi qua đối tượng sở hữu (dấu chấm `obj.fn()`) không? → Nếu có, `this` là `obj`. 4. Nếu không thỏa mãn cả 3 điều trên → Rơi về Default Binding: `undefined` trong strict mode, hoặc `global/window` trong non-strict mode."

🎓 Q2: Làm thế nào để khắc phục hiện tượng mất liên kết context khi truyền phương thức vào callback của setTimeout hoặc DOM Event Listener ?

Trả lời Top-Down chuẩn Senior :

"Có 3 cách phổ biến: (1) Dùng `Function.prototype.bind`: `setTimeout(obj.fn.bind(obj), 100)`; (2) Bọc trong một Arrow Function: `setTimeout(() => obj.fn(), 100)` vì arrow function kế thừa lexical this từ môi trường xung quanh; (3) Sử dụng ES Class Fields với arrow function: `fn = () => { ... }` gắn trực tiếp vào instance."
